## Objective

Make it possible, inside the `pekko-actor` package, to spawn a named actor whose parent is the `/system` guardian, with its own name table, so that the actor finishes its `PostStop` only after every `/user` actor finished and before `WhenTerminated` closes. The first consumer is the dead-letter listener of #1479 (an actor under `/system` subscribed to the event stream, as in Pekko `AS:1068-1069`); the next ones are the stream's unsubscriber (#1056 family), the Receptionist (#960) and the Typed `systemActorOf` (#1176), which are not part of this unit.

## Evidence: Pekko, the oracle, and what goPekko does today

**`systemActorOf`** (READ). `AS:772-779`: "Create an actor in the "/system" namespace. This actor will be shut down during system.terminate only after all user actors have terminated. This is only intended to be used by libraries (and Pekko itself)". It is declared in the public trait `ActorSystem` (not `private[pekko]`); the implementation is `AS:924-925`: `systemGuardian.underlying.attachChild(props, name, systemService = true)`. The name goes through `checkName` (`CH:64-65`, `CH:269-272`: null and empty are `InvalidActorNameException`, then the same rules as `actorOf`), and `attachChild` calls `makeChild` (`CH:279-340`): if the guardian's children container is terminating it throws `IllegalStateException("cannot create children while terminating or terminated")` (`CH:313-314`), otherwise it reserves the name in the **guardian's own** container (`CH:316`), where a live duplicate is `InvalidActorNameException("actor name [..] is not unique!")` (`CC:144`, `CC:209`; `CC:108` and `CC:206` for the terminated and terminating containers). So names are per guardian: `/user/x` and `/system/x` coexist. The public `actorOf` of `AS:927-935` attaches to the `/user` guardian the same way (`systemService = false`).

**The guardians** (READ). `ARP:538-599`: the root guardian is the parent of both; `guardian` (`/user`) is `ARP:558-584`; `systemGuardian` (`/system`) is `ARP:586-599`, created with `Props(classOf[SystemGuardian], systemGuardianStrategy, guardian)` and `systemGuardianStrategy = SupervisorStrategy.defaultStrategy` (`ARP:532`). `ARP:613-618` (`init`): `systemGuardian.sendSystemMessage(Watch(guardian, systemGuardian))` and `rootGuardian.sendSystemMessage(Watch(systemGuardian, rootGuardian))`: "chain death watchers so that killing guardian stops the application".

**The termination order** (READ). `AS:1089-1117`: `terminate()` ends in `finalTerminate()`, which stops the dead-letter listener only if `log-dead-letters-during-shutdown` is off (`AS:1115`) and then `guardian.stop()` (`AS:1116`). `SystemGuardian` (`ARP:331-374`) receives `Terminated(guardian)` (`ARP:339`): it switches to `terminating`, tells the registered termination hooks and, when none is left, stops the default loggers and `context.stop(self)` (`ARP:366-370`). Stopping a cell stops its children first and runs its `PostStop` only after they all finished: `FH:180-212` (`terminate()`: `children.foreach(stop)` at `:188`, the cell waits while it has children, `:200-207`) and `FH:247-276` (`finishTerminate`: `aroundPostStop` at `:254`, then the `DeathWatchNotification` to the parent at `:263-264`). The root guardian is watching `/system` and stops itself on any `Terminated` (`Guardian`, `ARP:315-326`, line `:320`); its death reaches `theOneWhoWalksTheBubblesOfSpaceTime`, which completes the termination promise (`ARP:448-487`, `:476-484`, `:483`), that is `WhenTerminated`. Hence the relations: `/user` finishes, then `/system` guardian stops its children (the system actors), then finishes, then the root, then `WhenTerminated`. A system actor spawned while `/user` is still terminating is accepted (the `/system` guardian is not terminating yet) and is stopped with its guardian.

**Not part of this unit** (READ, `ARP:297-307` and `:336-370`): `RegisterTerminationHook`, `TerminationHook` and `TerminationHookDone`; `ActorSystem.stop(actor)` routing a `/system` child through `systemGuardian ! StopChild` (`AS:939-948`).

**Oracle.** None observes the stop order of `/system` actors against `/user`. The event-stream oracle (`docs/parity/oracles/eventstream-spec-2026-11-06.md`, EV7 to EV9) used `systemActorOf` for its harness actors and saw `/system/eventStreamUnsubscriber-1` exist and be terminated after `whenTerminated` (its lines 211 and 222), and says the order in which it stops relative to other system actors "was not studied". The order of `AS:773-774` is READ only. **Proposed (D-6): a small Pekko oracle on Java 8** (the method of `restart-stash-held-2026-11-11.md`): a `/user` actor and a `/system` actor created with `systemActorOf`, both with a `PostStop` spy, a `/user` `PostStop` held by a latch, `system.terminate()`; log the order of the two `PostStop`s and the completion of `whenTerminated`; a duplicate name and an invalid name under `/system`; a `systemActorOf` called after `terminate()` began and again after `whenTerminated` completed. Without it, the order rows are READ and `pending approval` (ADR 0033 D13).

**goPekko today** (read at `dbdf15b6` and again at `94c41305`, the cited files unchanged). The guardians exist and are actors: `startGuardians` (`guardian.go:168-189`) builds the root, `/user` and `/system` (`guardian.go:177`, `DefaultStrategy`), `wireGuardians` links the Watch chain (`guardian.go:146-152`), and the `guardian` actor stops itself on any `Terminated` (`guardian.go:24-31`, `OnTerminated` then `ctx.StopSelf()`, after `ARP:320`). But `System.spawnTarget` returns the `/user` node and `/user` as parent only (`hierarchy.go:23-25`), and `guardianSet` keeps only that node (`guardian.go:112-115`, set at `:178`), so nothing can be spawned under `/system`; `eventstream_watch.go:15` says "goPekko has no /system actor (#1055)". The termination order of the three guardians is already promised and tested (`pekko-actor/README.md`, section "Termination of the System (U10, #192, #193)", and `system_shutdown_internal_test.go`); what is missing is a child of `/system` that exercises it. The top-level `Spawn` returns `ErrSystemStopping` from the first `Terminate` (`spawn.go:81`, `:115-116`, only for an owner of type `*System`).

## Proposed Go form (for the Owner at G2)

No exported symbol. Inside `pekko-actor/actor`:

- `guardianSet` gets a field `systemNode *node`, set in `startGuardians` next to `userNode` (`sysg.node`).
- `type systemSpawner struct{ s *System }` with `spawnTarget()` returning `spawnTarget{sys: s, owner: s.guards.systemNode, parent: s.guards.system}`, and `func (s *System) systemSpawner() Spawner`. `Spawn[T](s.systemSpawner(), "name", factory, opts...)` then goes through the existing path (`commitCell`: name validation, reservation, factory timing, the gate of the node). Because `spawn.go:115` translates `ErrParentStopping` to `ErrSystemStopping` only when the owner is a `*System`, a refusal under `/system` stays `ErrParentStopping`.
- No change to `Terminate`, to the guardian actor, to the Watch chain or to the guardian strategies.

Mutations MS1 to MS10 are applied by hand on a copy and are of two classes, kept apart. **ORDER and RESULT** mutations (MS1, MS2, MS3, MS4, MS6, MS7, MS8, MS9, MS10) must fail by an assertion of the test, never by a compile error, a hang or the timeout of the test runner; they are the detections the QA reproduces and counts. **LIVENESS** mutations (MS5 only) lose the termination itself, so the only observable is that `WhenTerminated` does not close: a focused test may assert "`WhenTerminated` closes within a short deadline", and that failed assertion is the evidence of the loss; it is reported as liveness evidence of this unit's tests, not as a detection by the judge (the judge's rules do not admit a timeout as a detection, and this unit adds no judge scenario and changes nothing under `judge/`). Every wait of every test carries a short deadline.

**Schedule of S8 and MS10 (a proposed design for the Dev's test; nothing was executed, and the Dev confirms each step against the real code when writing it).** Holding the `PostStop` of the `/user` actor until the dead letter is observed does not by itself force MS10 to fail: with the premature stop of `/system` queued, an executor may deliver the event first and run the stop afterwards, and the assertion "the `/system` actor received the dead letter" would still hold. The interleaving is forced with the controlled executor the package already has (`ctlExec`, `cell_internal_test.go:23-72`, injected through the System option `exec`, `system.go:27` and `:171`; the helpers `shdRunOne`, `shdRunSome` and `shdDrain`, `system_shutdown_internal_test.go:165-178`). That executor never runs a function inline and runs one only when the test asks, on the test's goroutine, with FIFO (`RunOne`), LIFO (`RunNewest`) and counted runs available; no sleep and no new production mechanism are needed. Because it runs on the test's goroutine, a `PostStop` "held" by a latch would block the test itself: with `ctlExec` the hold is an activation that the test leaves queued, and a latch is used only in a test that runs on the default executor (S3, S4, S5), where its release is registered before any fallible step.
1. Build a System with `ctlExec`; spawn the `/system` actor L (subscribed with `Subscribe[DeadLetter, DeadLetter]`), a `/user` actor U whose `PostStop` tells a stopped actor X, and X, stopped beforehand; drain, then assert the preconditions (L's subscription is registered, X is stopped, U has not stopped).
2. Call `Terminate`; assert that the stop of `/user` was accepted and that the queue is not empty.
3. Drive the queue with the adversarial order of the judge (`RunNewest`, the helpers with `lifo = true`) one activation at a time, and after each one check two observed facts: whether U's `PostStop` has run, and whether L's `PostStop` has run. The source implies that the correct code has no `/system` stop in the queue until `/user` finished (`system_shutdown.go:31` stops only `/user`), while MS10 adds the stop of `/system` right after it, so the newest queued activation under MS10 is the `/system` one and runs first; the Dev checks that queue order and, if it differs, picks another existing order or count (`RunOne`, `shdRunSome(k)`) that runs the `/system` stop chain before U's `PostStop`.
4. Assertions, in this order: (a) L's `PostStop` did not run before U's `PostStop` ran (this is what MS10 breaks, so MS10 fails here, by assertion); (b) after U's `PostStop`, the executor is drained and L received that dead letter exactly once; (c) L's `PostStop` ran after the event and before `WhenTerminated` closed. The steps that decide the interleaving are themselves asserted (U's `PostStop` ran, the queue was not empty), so a schedule that stops forcing anything fails the test instead of passing vacuously.
5. Cleanup (a proposed design for the Dev's test; nothing was executed). One `t.Cleanup` is registered right after the System is built and before any precondition or assertion that can fail, so it also runs when a precondition fails before `Terminate` was ever called. It does, in this order:
   1. Release every latch the scenario holds, each through a `sync.Once` (idempotent; a latch the scenario does not use is a no-op).
   2. Call `Terminate` before draining. It is idempotent (`system_shutdown.go:17-31`) and starts no goroutine of its own: the stop is carried out by the System's executor, so with `ctlExec` a queue that nobody drives terminates nothing, and after a precondition failure the stop of `/user` was never accepted at all.
   3. Run the queued activations with a finite budget: a loop of at most N calls of `shdRunOne` (N a named constant of the test, larger than the number of activations the scenario can queue), stopping early when the queue is empty and `WhenTerminated` is closed. No unbounded drain (`shdDrain` or `RunAll`): an activation may queue others, and a schedule that failed may never empty the queue.
   4. Check that `WhenTerminated` closed with a non-blocking read. If it did not close when the budget ran out, report the failure from the cleanup (`t.Error`) and return, without waiting.
   5. Never call `Shutdown` with an unbounded context while `ctlExec` has pending work: `Shutdown` waits in the caller's goroutine (`system_shutdown.go:43-52`) for a termination that only this same goroutine can run through the executor, so it would block the test forever. A timed wait that does not run the queue does not complete the termination either: it only expires and returns the context's error. Hence `Shutdown` is not part of the cleanup.
   For the scenarios that run on the default executor (S3, S4, S5), steps 1 and 2 are the same and the check of step 4 is a bounded wait on `WhenTerminated` (`awaitCh`), since the activations run on their own goroutines.

## Decisions of form (each with its Pekko citation; for the Owner at G2)

- **D-1. The form: no export in this unit (recommended).** Pekko declares `systemActorOf` in the public trait (`AS:779`) but says it is "only intended to be used by libraries (and Pekko itself)" (`AS:776-777`). In goPekko the only consumers today are inside the package (the listener of #1479, later the stream's unsubscriber); the external consumers (the Typed `systemActorOf`, #1176, the Receptionist, #960) have no scope yet. ADR 0011 owner decision 2 and EXP-1 ask a concrete consumer, the symbol, why the public API is not enough and its test, in the story that introduces the export; with no consumer there is nothing to justify, so the unit adds an unexported seam and a story that adds no export needs no record (EXP-1). Alternative B: export `func (s *System) SystemSpawner() Spawner` now; its EXP-1 consumer would be a story that is not written (#1176), and `Spawner` is sealed (`hierarchy.go:10-12`) so Typed could use the value but could not implement the interface. Not recommended. The wording of #1055 ("a way to spawn", "the smallest export") is read as "the smallest form", which is no export until a consumer needs it; **this is a change from the text of the issue and needs the Owner's decision**. Four consequences that belong to D-1 and are not editorial changes (the Owner decides them with it): the spawner stays internal and no symbol is exported in this unit; the criteria that asked for public tests become internal tests; the differential scenario of the original criterion is replaced by the oracle of D-6; and the form usable by Typed stays with the story that adds the export. In detail: (a) the acceptance criteria AC-R1-1, AC-R2-1, AC-R3-1 and AC-R4-1 of the issue say "Public-API Go test"; with no export there is no public way to create a `/system` actor, so all four become internal tests of package `actor` (S1 to S4 here), and the "differential judge scenario on Pekko" of AC-R3-1 is replaced by the oracle of D-6 (there is no judge scenario for it); (b) the note of ADR 0010 in the issue's ADR impact list (the form must work for `pekko-actor-typed` without opening the sealed `Spawner`) is not met by this unit, because no form reaches another module; it stays a requirement of the story that adds the export (#1176 or #960): a value of the existing type `Spawner` that `Spawn` accepts, with no new interface.
- **D-2. Own name table.** `systemNode` is the node of the `/system` guardian (`sysg.node`), so names are unique within `/system` only (`CH:316`, `CC:144`).
- **D-3. When a spawn under `/system` is refused (Owner decision named in the issue).** Pekko accepts it until the `/system` guardian is terminating (`CH:313-314`); that happens only when the guardian processes its own stop, after `/user` finished (`ARP:339`, `FH:200-207`). Recommended: the same in Go, i.e. the gate of the `/system` node, which closes when its stop is accepted; the refusal is `ErrParentStopping` (`spawn.go:115` is not applied to a `systemSpawner`). This differs from the top-level `Spawn`, which is refused from the first `Terminate` because that is the stop of `/user` itself; the two are consistent with Pekko, where each guardian refuses when its own container terminates. Alternative: refuse from the first `Terminate`; not recommended (it would break a library that registers a helper while `/user` drains).
- **D-4. No new mechanism for the order (R3).** The Watch chain and the guardian's `OnTerminated` already make `/system` stop after `/user` and the root after `/system` (`guardian.go:24-31`, `:146-155`; `pekko-actor/README.md`, section "Termination of the System (U10, #192, #193)"); a child of `/system` is stopped before the guardian's own `PostStop` by the hierarchical termination (ADR 0014; `FH:188`, `FH:254`). The unit proves it with S3 and S5 and adds no code to it. Known difference, not observable through this unit: the Go guardian stops on any `Terminated` it receives (one actor type for the three guardians), Pekko's `SystemGuardian` only on `Terminated(guardian)` and keeps `Terminated(a)` for its hooks (`ARP:338-349`); the `/system` guardian watches only `/user` and does not watch its children, so it receives no other `Terminated`. Recorded as `PORT-GAP(SYS-18-termination-hooks)` with `RegisterTerminationHook`, `TerminationHook` and `TerminationHookDone` (`ARP:297-307`, `:336-370`; out of scope in the issue).
- **D-5. No `StopChild` routing.** `ActorSystem.stop(actor)` routes `/user` and `/system` children through their guardian (`AS:939-948`) so that the stop is serialized with the guardian; `System.Stop(h)` stops directly and idempotently for any handle. No observable difference is claimed, S7 pins the Go behavior.
- **D-6. The evidence.** A Pekko oracle on Java 8 for S3, S4, S5 and S2 (above), as its own PR before the code slice (it can run in parallel with the kit and with the oracle of #1479); or READ evidence from the cited bodies, rows `pending approval` (ADR 0033 D13). Recommended: the oracle.
- **D-7. The stream's unsubscriber is not replaced here.** `eventstream_watch.go` keeps its internal `watcherLink` (ADR 0038 D6; the comment is updated only to say that the seam exists and that the replacement is a later story); `eventStreamUnsubscriber` under `/system` is not created.
- **D-8. Kit run and slices.** Kit run required; the oracle PR (D-6), then one code slice (below) with its kit package in a separate PR if the 400 budget needs it. **Conditional partition (a proposal, pending G2):** if the measured size of the code slice passes 400 authored lines, S7 and S8 with their tests move to a second code PR, so the unit is three PRs (oracle, code, kit) or, with that cut, four (oracle, code 1, code 2, kit). Every PR stays at or under 400 authored lines; the cut is decided by the measured size, never by an estimate, and no assertion or scenario is compressed or removed to fit a number.
