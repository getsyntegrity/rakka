# Oracle: what the restart stash of a Typed supervisor does with what it retained when the rebuilt behavior stops (Pekko v1.7.1)

- Date: 2026-11-11. Evidence only; this document recommends nothing and changes no ADR or scope.
- Pekko `actor-typed` 1.7.1 (tag `v1.7.1`, `upstream/pekko` at `9a54d1294c3ac7821bbed3c940769c3d5027d1ff`), Scala 2.13.18, **JDK Zulu 1.8.0_504**: every sbt run was started with `-java-home` of that JDK and its first line says `Java 1.8.0_504`; every harness log starts with `java.version=1.8.0_504 java.home=.../8.0.504+1-zulu/jre` and ends with `exit=<code>`; see `env.txt`. Default fork-join dispatcher (`parallelism-max = 4`). A Typed actor is spawned on a Classic `ActorSystem` through `pekko.actor.typed.scaladsl.adapter._` (`system.spawn`), as in `unstash-deadletters-2026-11-10.md`.
- Purpose: QA of PR #1545 (slice B of #1182, `docs/scopes/1182-typed-stopped.md`) rejected the head `bdd0196b` because part of criterion R8 is *inferred*, not observed: the dead letter that a **`Terminated` signal retained in the restart stash** becomes when the rebuilt behavior stops (PR #1545 publishes it as `SuppressedDeadLetter(Terminated, deadLetters, deadLetters)`). The Owner's decision of 2026-11-10 on #1524, point 3, asks for observed values here. The questions: (a) for the **user messages** retained in the restart stash, which `DeadLetter` is published, with which sender and recipient (the oracle `W3c` of `typed-restart-child-wait-2026-11-06.md` observed only their count and order); (b) for a **`Terminated` signal** retained there, whether `DeadLetter`, `SuppressedDeadLetter` or nothing is published, with the exact message class, sender and recipient.
- Method: code reading (section 1); Option 1, the shipped spec `org.apache.pekko.actor.typed.SupervisionSpec` in a `git archive v1.7.1` copy (section 2); Option 2, new scenarios `RS0` to `RS3` in `docs/parity/harness/src/main/scala/restartstash/Run.scala` (sha256 in `harness-files.sha256`), each in its own JVM, three runs, with three collectors on the event stream (`DeadLetter`, `SuppressedDeadLetter`, `AllDeadLetters`) printing class, message, sender and recipient (section 3). Raw logs are complete and untrimmed in [`restart-stash-held-2026-11-11.logs/`](restart-stash-held-2026-11-11.logs/README.md). Citations `[nnn]` are lines of run 1 of the named file; runs 2 and 3 are compared as sets of lines. Anything not shown by a log line is marked *inferred*.

## 3. Option 2: scenarios `RS0` to `RS3`

Common method (the shape of `W3` in `typed-restart-child-wait-2026-11-06.md`): `A` is `Behaviors.supervise(setup { ... }).onFailure[IllegalStateException](SupervisorStrategy.restart)`. Its first `Setup` spawns a child `c1` whose `PostStop` blocks on a latch the harness controls, and watches an actor `X`. The harness tells `"fail"` (A throws), waits until the log shows `c1 PostStop begin` (the restart is waiting for its child), and then sends what the scenario needs; to prove that the supervisor has *retained* each event before the latch is released, a hook placed **outside** the supervisor (`Behaviors.intercept` around `supervise`; it only delegates to it) logs `hook: supervisor returned for message|signal ...` and counts it, and the harness waits for that count, so the stash content is established by a counter and not by a sleep. The latch is then released, the restart completes (the `Terminated(c1)` signal), `Setup` runs again (`setup#2`, no children) and the supervisor replays the stash. `StopNow` makes the rebuilt behavior return `Behaviors.stopped`. The harness waits until `A` is terminated (a classic watcher), then fences the three collectors (a direct message from the publishing thread, queued behind earlier deliveries), so "nothing else arrived" is shown by a fence. `dl` = `DeadLetter`, `sd` = `SuppressedDeadLetter`, `all` = `AllDeadLetters` collectors; `dls` = `Actor[pekko://rst/deadLetters]`; `A` = `Actor[pekko://rst/user/A#uid]`.

All 12 runs ended with `exit=0` (`exitcodes.txt`) and every log starts with `java.version=1.8.0_504`. ## 4. Findings and comparison with the code reading

- **(a) The retained user messages are `DeadLetter(msg, deadLetters, A)`** (`RS1` [019, 021]): message = the retained message unchanged, sender = the Classic `deadLetters` (`sender eq deadLetters = true`), recipient = the stopping actor itself (`recipient eq deadLetters = false`), in the order retained, once each. Same result as `US1` of `unstash-deadletters-2026-11-10.md` for a `StashBuffer` created by the user; here it is the restart's own stash.
- **(b) A retained `Terminated` signal is an ordinary `DeadLetter`, not a `SuppressedDeadLetter` and not discarded** (`RS2` [017]): `message = Terminated(X)` of class `org.apache.pekko.actor.typed.Terminated`, `sender = deadLetters`, `recipient = A`; no `sd recv` line and no `Terminated` signal reached the stopped `A` in any of the 3 runs. This is what the code reading predicts (P2, P4, P5, P6): the stash holds the **Typed** signal, which is not a `DeadLetterSuppression`. It differs from `US6` of the previous oracle (a `Terminated` queued in the *user queue*, the Classic one, published as `SuppressedDeadLetter(Terminated(B), sender = B, recipient = deadLetters)`): the two are different routes.
- **The control shows that the stash carries the signal** (`RS0` [015, 016]): without a stop, the rebuilt behavior receives `m1` and then the Typed `Terminated(X)` signal, in arrival order, and nothing is dead-lettered.
- **A `DeadLetterSuppression` *message* retained in the stash is suppressed as usual** (`RS3` [017]): `SuppressedDeadLetter(SuppMsg, sender = deadLetters, recipient = deadLetters)`, the same value as `US4` of the previous oracle; the neighbouring plain message is a `DeadLetter` (`RS3` [019]).

## 5. Differences from the code reading

None. P4 to P6 predicted each of these values. The value that PR #1545 (`bdd0196b`) publishes for the retained `Terminated` (`SuppressedDeadLetter` with sender `deadLetters` and recipient `deadLetters`) is **not** what this oracle observed; this document does not say what the Go side should do.

## 6. Limits of this evidence

- Local, Classic `ActorSystem` hosting Typed actors, default dispatcher, one JVM per run, Java 1.8.0_504 only; no remote, no cluster.
- The messages are told from the main thread (a Typed `!` has no sender), so the sender of a retained user message is always `deadLetters` in these runs; the restart stash never carries the original sender (P4).
- The `Terminated(X)` is retained because `X` stops while `A` waits; the hook `Behaviors.intercept` is outside the supervisor and was part of every run (it only delegates to the supervisor and logs). A run without the hook was not made.
- `ChildFailed` (a failing *child* other than the awaited `c1`), `watchWith`, `PostStop`/`PreRestart`-type signals retained, and a `Terminated(X)` made while the system queue still holds the death-watch notification of `A` were not run. The case "`Setup` of the rebuilt behavior is itself `Behaviors.stopped`" (the initial behavior not alive) was not run in the restart stash; the unrelated `StashBuffer` case is `US3` of the previous oracle.
- The stash was well below its capacity (`restart-stash-capacity` default 1000); a full stash (`Dropped`) was not run here (`W3d`, `W3e` of `typed-restart-child-wait-2026-11-06.md`).
- The harness package `restartstash` is new and reuses `Log`, `Collector`, `Fences` and `Watcher` of the `unstash` package; the harness depends on `pekko-actor-typed` 1.7.1 from Maven Central, not from the `git archive` copy; Option 1 used the build of the copy.
- Timing: the duration of the 12 JVM runs was not measured.
