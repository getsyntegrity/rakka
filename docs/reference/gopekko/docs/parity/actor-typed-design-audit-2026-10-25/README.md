Detail per subsystem lives in `reader-reports/*.md` (11 files, ~410 KB, with path:line evidence). This file is the consolidation. It claims no parity and accepts no decision.

## 2. Verdict
**The design is NOT closed.** Typed has zero code; Classic is the local core only. What is closed: scope/architecture (ADR 0033 D1–D13 accepted) and ADR 0031 (paths), ADR 0030 (bounded mailbox). What is not: Typed `Behavior[T]` boundary (#809, no ADR), Typed supervision (#1063, no ADR), per-export ADR 0011 justification (#1020/#1021), the sender contract (ADR 0032 unmerged), AskFrom (ADR 0010 D4/D7 vs 0015 D1/D7), the ADR 0010 exclusions (ADR 0010 is only `proposed`), the judge/inventory for the rows listed in jdg-cls-tkt F1 that have Pekko source or specs but no judge scenario story, and ~25 GOV decision stories with no Owner artifact.

Review depth achieved (421 stories): **239 DEEP, 175 SHALLOW, 7 NOT REVIEWED** (all 7 in TYP: #958 #978 #982 #983 #988 #989 #990). Typed (#763) is only 2/51 DEEP, EVT/PAT/SER 21/52, RTE/FSM/IO 20/53, SUP/SYS 30/50. SHALLOW = body + reconciliation + Pekko source lines checked, spec bodies not traced per AC. I did not independently re-verify most reader claims; I spot-checked two (see §11). A fidelity pass on 2026-10-25 re-checked reader claims against Pekko v1.7.1 and applied the corrections in this PR; claims not re-checked remain unverified.

### 13.3 Tension with ADR 0033 D2 (not resolved here)

1. D2 words the default as a profile selected when the actor is created. In Pekko the same Stop is produced by two mechanisms that depend on the parent kind: parent side for a Typed parent, child side (a supervise wrapper installed at the Classic-side spawn entry points) for a Classic parent.
2. D2 does not describe what a Typed parent does with a Classic child. Pekko applies the Classic `defaultDecider` to the child's failure (13.1.1): Stop for `ActorInitializationException`, `ActorKilledException` and `DeathPactException`; Restart for other `Exception`; Restart as the fallback for other non-fatal throwables (code only for the last fallback). Which of these outcomes is shown by a spec is stated per row in 13.1.1.
3. D2 does not describe the parent-side logging and cause recording (`ChildFailed`), which only a Typed parent does and only for watched children.

4. A Classic child does not follow the same decider under both parent kinds for every throwable. For a `Throwable` that is not an `Exception`, a Typed parent answers Restart (`ActorAdapter.scala:57`) and a Classic parent escalates (`FaultHandling.scala:309,372`, rethrow `dungeon/FaultHandling.scala:314`). Both readings are from code; no spec was found.

The specs read exercise: a Typed child stopping under a Typed or Classic parent; a Classic child under a Typed parent that throws a `RuntimeException` while processing a message (restarted) or from its constructor (reported as `ActorInitializationException`, stopped); and, under a Classic parent with the default decider, `Kill` and `DeathPactException` (indirectly, `DeathWatchSpec.scala:216-246`). All other rows of 13.1.1 are code only. Whether the wording of D2 is observably equivalent in the situations not exercised is open (13.5).

### 13.4 Proposed addition to ADR 0033 D2 (Architect proposal for the Owner; ADR 0033 is not edited and nothing here is accepted)

This proposal does not replace the accepted sentence of D2 ("A profile is selected when the actor is created and does not change the behavior of the other profile."). Whether to keep it, add to it or replace it is the Owner's decision. The text below is limited to the cases observed in both code and specs (13.1):

> In Apache Pekko v1.7.1, a Typed actor whose behavior throws is stopped by default, both under a Typed parent and under a Classic parent. A Classic actor supervised by a Typed parent is restarted when it throws a `RuntimeException` while processing a message, and is stopped when its constructor throws (reported as `ActorInitializationException`). (Specs: `WatchSpec.scala:100-160`, `ClassicSupervisingTypedSpec.scala:74-160`, `TypedSupervisingClassicSpec.scala:61-72`, `AdapterSpec.scala:317-343`.)

Cases this text does not cover, and for which the amendment stays incomplete until the initialization, supervision and escalation paths are inspected (13.1.1 and 13.5):

- A Classic child under a Typed parent that throws an `Exception` other than a `RuntimeException`, or `ActorKilledException`, `DeathPactException`, `PreRestartException` or `PostRestartException`: the Classic `defaultDecider` answers Stop for the last four and Restart for other `Exception`, code only (the decider matches by class); no spec found under a Typed parent.
- A Classic child under a Classic parent: Restart, Stop and Escalate by failure kind, code only; `Kill` and `DeathPactException` are observed indirectly by `DeathWatchSpec.scala:216-246`.
- A non-fatal throwable that is not an `Exception`: a Typed parent answers Restart and a Classic parent escalates (code only, no spec found); the grandparent path after an escalation was not traced.
- An explicit restart or resume strategy on a Typed child: code only for the Typed-parent case.
- Failures during actor initialization outside the behavior, the Typed user guardian, and the parent-side recording of the cause for `ChildFailed`.

The text does not state how goPekko realizes these outcomes; that belongs to the Typed supervision ADR (#1063). Alternatives to adopting it are in OD-1 of `reader-reports/typ.md` (section 4).
