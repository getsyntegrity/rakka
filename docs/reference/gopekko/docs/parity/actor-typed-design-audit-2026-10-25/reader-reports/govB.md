## 3. Findings

Severity: blocker / high / medium / low.

**F-1 (high). Owner decisions for GOV-45/46/47 (and GOV-15 cited by GOV-48) are asserted only by Architect-edited issue text; no Owner artifact.**
Evidence: X1; GOV-45/46/47 bodies "Owner decision recorded on 2026-10-25"; header of the same block still reads "Architect, 2026-10-24"; issue `updatedAt` 2026-10-25T03:27-04:27Z; `docs/adr/` has no record; R5/AC-R5-1 of each story still require the field to read `pending` (the block says the AC "is superseded"). Under the brief's rule ("unambiguous recorded Owner decision") the wording is unambiguous but the record is in the graded party's own text.
Minimal correction: Owner posts a comment (or an ADR/PR) on each issue naming the option, then the Architect links it; or the decisions are re-labelled "Architect-recorded, Owner confirmation pending". Do not treat SER-07/08/11 as unblocked by it (they remain `status:blocked`, correctly).

**F-2 (high). GOV-35: cited spec does not exist.** Story traceability: "ReceptionistApiSpec.scala (ReceptionistSetup usage; line not verified)". `grep ReceptionistSetup` over all `*.scala *.java *.md *.conf` in `upstream/pekko`: only `Receptionist.scala:465-477`. `actor-typed-tests/.../receptionist/ReceptionistApiSpec.scala` exists but has no `ReceptionistSetup`. So there is no Pekko oracle; option A (`owner-excluded`) is a pure Owner decision with source-only evidence.
Correction: replace the spec cell with "no spec found; searched ReceptionistSetup in all sources".

**F-3 (high). GOV-32 misdescribes what Pekko checks; recommended reason `jvm-only` rests on that.** Story: "Pekko checks that a Props creator can be serialized ... creator is a JVM closure checked with Java serialization". Source `Children.scala:286-306`: the check serializes+deserializes each of `props.args` through the configured `SerializationExtension` (any serializer, not Java serialization), is skipped for `NoSerializationVerificationNeeded` args, for configured class prefixes, for system services and for `deploy.scope == LocalScope` (`reference.conf:130-136` says "Purely local deployments as marked with deploy.scope == LocalScope are exempt"), and throws `IllegalArgumentException("pre-creation serialization check failed at [path/name]")`. The story cites only `ActorSystem.scala:430` and `reference.conf:136`, never `Children.scala:286`. Pekko observed: default `Props` (`NoScopeGiven`) are checked, local-scope are not; `reference.conf:133-136` states the feature is intended for testing and to verify creators can be sent over the network. The story's premise ("JVM closure checked with Java serialization") does not match this. (ii) it is a round-trip of arguments, the same primitive as `SerializationTestKit.verifySerialization` (GOV-27) and SER-06. Open question: the exclusion reason for GOV-32; no recommendation.
Correction: cite `Children.scala:286-306`, restate the behavior, and link GOV-27/SER-06.

**F-4 (medium). GOV-27: premise "D10 already omits SerializationTestKit" is incomplete.** `ActorTestKit.scala:327` exposes `serializationTestKit`; D10 includes `ActorTestKit`. Excluding `SerializationTestKit` therefore also removes a member of an included facade. Also the "no spec" cell is blank where the honest value is "no dedicated spec found" (ActorTestKitApiTest.java:35 only obtains the instance).
