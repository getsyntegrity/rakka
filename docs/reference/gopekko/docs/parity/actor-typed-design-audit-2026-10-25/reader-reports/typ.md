## 3. Findings

**F1 (high) #809 / #847 AC text on validateAsInitial is wrong.** Reconciliation says validateAsInitial "rejects deferred/same/unhandled as initial behavior (Behavior.scala:240)". Pekko rejects only SameBehavior and UnhandledBehavior, with IllegalArgumentException (Behavior.scala:240-243; doc :236-239 says Stopped IS allowed). A deferred (setup) behavior is started first and the RESULT validated (ActorAdapter.scala:301-303); a setup that yields same therefore surfaces as ActorInitializationException (DeferredSpec.scala:147-158). Also: Behavior.scala:281-296 makes interpret throw IAE for same/unhandled/deferred/supervise, and a null behavior throws InvalidMessageException only inside interpret (:286). Correction: rewrite the three AC lines of #809 as observable outcomes (failed start vs IAE), cite DeferredSpec:147, WatchSpec:165/199 and ActorContextSpec:527 (DeathPact), drop OrElseSpec (see F5).

**F2 (high) Pekko's default failure outcome depends on parent kind and child kind; ADR 0033 D2 words it as a profile selected at creation.** Pekko observed (code and specs, see README section 13 for the four cases): a Typed parent's strategy (ActorAdapter.scala:232-266) answers Stop for a Typed child and, for a Classic child, `classicSupervisorDecider` (ActorAdapter.scala:55-58, i.e. the Classic `defaultDecider`: Stop for `ActorInitializationException`, `ActorKilledException` and `DeathPactException`, Restart for other `Exception`, and Restart as fallback for other non-fatal throwables; FaultHandling.scala:218-222; per-failure evidence in README section 13.1.1); under a Classic parent a Typed child is created wrapped in `supervise(..).onFailure(stop)` and stops itself (ActorAdapter.scala:168-172). The typed parent also logs at ERROR and records the cause for `ChildFailed` only when it watches the child (:257, :268-273, :94-100). Specs read: ClassicSupervisingTypedSpec.scala:74-160, TypedSupervisingClassicSpec.scala:61-72, AdapterSpec.scala:317-343, WatchSpec.scala:100-160. goPekko design decision in force: ADR 0033 D2 (accepted); #956 AC3. Tension: D2 says a profile is selected when the actor is created and does not change the other profile; it does not describe the Typed-parent behavior toward Classic children, the two Stop mechanisms, or the parent-side cause recording. This audit does not resolve it. Pending recommendation: none from this audit; a concrete amendment text for the Owner to accept or reject is in README section 13. Open questions with the evidence still missing are listed there.

**F3 (high) #927 conflates three interruption outcomes.** Reconciliation: "stopped or failed Behavior interrupts replay; remaining messages go to dead letters". Pekko: (a) result not alive (stopped OR FailedBehavior) or initial behavior not alive -> remaining messages dead-lettered as DeadLetter(wrap(msg), deadLetters, self) (StashBufferImpl.scala:233-243, 246-251); (b) a thrown exception -> UnstashException(e, b2) (:206) and the REMAINING MESSAGES STAY IN THE BUFFER because dequeue is lazy (dropHeadForUnstash :104, iterator :171-176); (c) unhandled start behavior -> IAE (:229-230; pinned by StashBufferSpec.scala:261-265); unhandled message result -> ctx.onUnhandled and replay continues (:211-213); stashed Signals are replayed through interpretSignal (:202). StashSpec.scala:688-710 pins only (a)-stopped. Correction: restate #927 AC3 as the three cases; evidence: (a) StashSpec.scala:688-710 plus code StashBufferImpl.scala:218-223,238-251; (b) code only (not proven by a test read); (c) StashBufferSpec.scala:261-265. (b) is observable Pekko behavior (code: StashBufferImpl.scala:205-207, ActorAdapter.scala:143-153; "remaining messages stay in the buffer" follows from the lazy iterator at :170-178 and is not shown by a cited test); UnstashException is unwrapped by Supervision.scala:75-76 (also :102, :174, :318, :327). Which goPekko ADR records it is an open question; no recommendation.

**F4 (high) #1169 is transitively blocked on an ADR that is not in develop, and overlaps #927.** AC-R2-2 asserts the dead-letter sender is deadLetters; Go `DeadLetter` has no sender field (deadletter.go:22-25), so it needs #814 MSG-02 whose design is tied to ADR 0032 D5 (open; ADR 0032 exists only on PR #1014). The story and #927 cite "ADR 0032 D3/D4/D6" as authority although those are not in develop (brief rule). #927's reconciled AC ("remaining messages go to dead letters as DeadLetter(wrap(msg), deadLetters, self)") duplicates #1169 AC-R1/R2; two stories own one behavior. The plan (J-02a) still says "NEW-20 (suggested; none published)" and has zero rows for TYP-34..51 (grep count 0 in actor-typed-delivery-plan.md). Correction: make #927 AC3 reference #1169 instead of restating; record that the sender assertion cannot be tested until #814 and an accepted sender ADR exist (the delivery plan O-4, resolved by the Owner, says to record and test Pekko's observed `deadLetters` sender; ADR 0033 D13 then asks for a differential scenario); add TYP-34..51 to the plan or mark the plan stale.
