## 3. Findings

**F-1 (high) #1155 AC-R3-1 contradicts Pekko; ack has no oracle.** AC-R3 says Deregister for a non-registered ref must still reply Deregistered. `LocalReceptionist.scala:195-199`: when the ref has no registration under ANY key the receptionist does `Behaviors.same` with no reply ("saw a terminate message before we got the deregistration"). Conversely, `:200-216`: Deregister(K2, svc) where svc is registered only under K1 DOES reply and re-notifies K2 subscribers. Also AC-R1's evidence "port of LocalReceptionistSpec :91,103,127" does not assert `Deregistered` (all three call `Deregister(key, ref)` without replyTo and observe Listings); no LocalReceptionist spec asserts `Deregistered` (searched actor-typed-tests, actor-typed/src/test, actor-testkit-typed). The ClusterReceptionist spec asserts the ack (cluster-typed .../ClusterReceptionistSpec.scala:656-657,713-714,766-768); whether it is an applicable oracle for the local receptionist is pending verification (missing: ClusterReceptionist.scala Deregister handling not read). Correction: rewrite AC-R3 to "no reply, receptionist keeps serving Find", add a case for "registered only under another key", the ack assertion's oracle status is pending verification as above; the "reply on a ref with no registration under any key" case is code-only for LocalReceptionist (LocalReceptionist.scala:195-199), not shown by a test. Source evidence only for the ack; Pekko test exists for listing effects.

**F-2 (high) ResendFirst is unconditional and producer-driven; three issues misassign it.** `ProducerControllerImpl.scala:421-423` starts the `ResendFirst` fixed-delay timer whenever the first message is sent (no durable-queue condition); `:675-685` handler; `:697-709` also on RegisterConsumer with unconfirmed; setting `durableQueueResendFirstInterval` (default 1s, `reference.conf` producer-controller.durable-queue.resend-first-interval) is misnamed. Spec `ProducerControllerSpec.scala:47` 'resend lost initial SequencedMessage' is non-durable. The #810 reconciliation ("producer resends only via ResendFirst for durable state"), #998 (`ResendFirst belongs to ... #1002`) and #1165 ("ResendFirst for the durable path: #1159") are all wrong (per the reader's reading of the issue bodies). The producer DOES push a resend of the first message without being asked (and Request(viaTimeout) triggers resend of the last). Correction: put non-durable ResendFirst in #998 (rescope text "consumer-driven resend plus first-message resend"), keep only the durable-restart use of it in #1159, and make the setting part of #1162 regardless of durable queue; fix the three reconciliation texts. Pekko test: `ProducerControllerSpec:47` (body read: ProducerControllerSpec.scala:47-72).

**F-3 (high) #963 AC-R3-1 ("does not send user messages before accepted demand") is contrary to upstream.** `ProducerControllerImpl.scala:56-66`: the ProducerController "sends the first message to the ConsumerController without waiting for a Request"; initial `requestedSeqNr = currentSeqNr` (`:254`) and `RequestNext` is issued at start (`:330-334`). Only messages after the first obey demand. Correction: reword AC-R3 to "after the first message, no message beyond requestUpToSeqNr"; record the first-message exception in #810.

**F-4 (high) #963 AC-R2-1 "a stale controller registration cannot hijack a later session" is not an upstream rule, and upstream behavior is the opposite for first messages.** `ConsumerControllerImpl.scala:108-109` (`isProducerChanged` = different producerController OR receivedSeqNr == 0), `:373-390` (`receiveChangedProducer`: accepted whenever `seqMsg.first || !resendLost`, switching producer even if another is active); non-first from a different producer after the first is discarded with a warn (`:403-410`); `registering` suppresses only non-changed-producer messages (`:313-318`). The reconciliation already says "needs explicit Go contract in #810" but #810's ACs do not list it. Correction: add an explicit AC to #810 (alternatives: keep Pekko's "newest first-marked producer wins" or add Go-only generation/session guard); the D13 classification of the Go-only variant is pending determination (no Pekko behavior found for it).

**F-5 (medium-high) Missing dependency edges and priority inversions inside the delivery lane.**

Edge #1162 -> #980/#1158/#1165 missing, wrong priority (P2 gates P1).
- #1163 (P2) is the worker-side ConsumerController-with-ServiceKey; every WorkPullingSpec case spawns `ConsumerController(workerServiceKey)` (`WorkPullingSpec.scala:66-72`) and #1157's AC evidence needs "two ConsumerController test workers". #1001/#1157/#1003 do not list #1163; P2 gates P1.
- #977 (TYP-15 timers, P2) gates P1 stories #963, #998, #1001.
- #1160 AC-R3 is "evidenced only after #1003" but no edge.
- #1003 `depends_on #998` ("unconfirmed tracking and resend"): reassignment is done by the WP controller itself (`WorkPullingProducerControllerImpl.scala:598-600`) and does not need the consumer-driven resend; edge is doubtful (needs #1001/#1157 state, not #998).
Correction: add the edges, raise #1162/#1163/#977 to the max of their dependents or lower dependents' priority, drop #1003->#998 unless justified.

**F-6 (medium) #1158 TSD-20 AC-R2: overflow is an actor failure, not a returned error.** `WorkPullingProducerControllerImpl.scala:236-238`: `throw new IllegalArgumentException(s"Buffer is full, size [${stashBuffer.size}].")` -> under typed default supervision the controller stops and unconfirmed state is lost. The AC says "documented error naming size 2 is produced" without saying where. No Pekko test covers it (grep "Buffer is full\|bufferSize" in actor-typed-tests: no hit). The Go choice (fail the controller, reply error, Dropped) is a contract needing the Typed supervision ADR (O-9 missing) and a D13 classification (oracle applicability pending determination). Also AC-R1 evidence cites 'work with fast producer and slow consumer' as a WorkPullingSpec test at :128: that test is in `ReliableDeliverySpec.scala:128` (point-to-point, `testWithDelays`), not WorkPullingSpec (5 tests: :60,:93,:147,:189,:244). Same mis-citation in #1157 (:124 and :136 are `ReliableDeliverySpec`). Correction: cite `WorkPullingSpec.scala:60` (usage) and add "no spec found for buffer overflow".

**F-7 (medium) #1157 open choice "weighted pick" is wrong.** `WorkPullingProducerControllerImpl.scala:401-412`: uniform `ThreadLocalRandom.nextInt(workers.size)` over workers with demand, excluding "preselected" workers (those already chosen while a store is in progress, `:402-404`). Correction: replace "weighted" by "uniform random among workers with demand and not preselected" (WorkPullingProducerControllerImpl.scala:401-412; code only, WorkPullingSpec bodies not read for selection). Pekko has no random-source injection point; how goPekko tests it is an open question; no recommendation.
