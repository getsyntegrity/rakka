## Key Learnings

1. In Pekko v1.7.1 `ActorAdapter.preRestart` sets the behavior to stopped, so `postRestart` stops the actor and the original Behavior is re-run only by `Supervision.scala` restartCompleted.
2. Typed `MailboxSelector.bounded(capacity)` is converted by Classic `Mailboxes` into `BoundedMailbox(capacity, Duration.Zero)`, so the zero push-timeout variant is the Pekko Typed behavior.
3. `AskSpec.scala` lines 96-105 show that a plain message sent to `Behaviors.empty` is published as an unhandled message, so some spec does observe the empty behavior outside the adaption-failure signal.
4. `ActorAdapter.next` is at lines 164-180 in v1.7.1, so citations of lines 174-190 for that method are about ten lines too high.
5. Typed timers are shared by the actor context and survive behavior replacement, as shown by the TimerSpec test "keep timers when behavior changes".
