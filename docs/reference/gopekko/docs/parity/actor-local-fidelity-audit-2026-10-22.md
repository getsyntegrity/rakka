## Verdict on `byID` retirement (ADR 0024)

It preserves the observable Pekko contracts, with evidence in code and tests:

- **Tell to a stale ref → dead letter**: `ref.Tell` uses its own cell and never reads the registry (`ref.go:43-51`); pinned by `registry_characterization_internal_test.go:265` and `registry_retention_internal_test.go:55`.
- **Watch on a stale ref → immediate `Terminated`**: `lookup` returns nil and the watcher is notified at once (`watch.go:111,168-169`); pinned by `registry_retention_internal_test.go:304` and `watch_internal_test.go:383`.
- **Stop and Unwatch on a stale ref** are no-ops (`stop.go:21`, `watch.go:226`).
- **Same-name respawn**: the name is released before watchers are told (`stop.go:107`); the old ref keeps reporting terminated (`registry_retention_internal_test.go:280`).
- **Identity**: IDs are never reused, so a removed entry cannot alias another actor.
- **Ordering**: retirement happens after `close(done)` and after watchers are notified (`hierarchy.go:228-243`), so a parent outlives its children's entries.
- **Residual**: `Done(h)` on a bare-ID handle for a retired actor returns `ErrUnknownHandle` (`system.go:152-158`, documented, Go-only). #563 (T6) is a memory concern only.
