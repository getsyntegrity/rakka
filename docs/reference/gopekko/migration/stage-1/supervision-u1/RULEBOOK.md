## 1. Decisions this RULEBOOK asks the Owner to confirm by approving its hash

- **D1 invalid directive error (A2).** `ErrInvalidDirective error = errors.New("actor: decider returned an invalid directive")`, exported (the grandparent's decider sees it as a cause, so `errors.Is` must be possible). It is the cause with which the parent fails when the decider returns `ok == true` and a directive that is not one of the values U1 delivers. Go-specific rule, **no upstream equivalent**; the coincidence with Pekko's `MatchError` for `null` (ADR 0017 A2, `a2a4-sbt.out`) is an observation, not an equivalence.
- **D2 the delivered directives.** `Directive` keeps the stub values (`Resume = 1`, `Restart = 2`, `Stop = 3`, `Escalate = 4`, zero invalid). Only `Resume`, `Stop` and `Escalate` are exported in U1 ("a directive is exported only when its semantics land"). **The value 2 is not delivered**: `Directive(2)` returned with `ok == true` is invalid (D1) and is never mapped to another behavior.
- **D3 causes.** A `Receive` that returns an error: the cause is that error unwrapped as returned. A panic: `*PanicError{Value}` exported as in the stubs (the same cause for a panic in the decider). `InitializationError` and `ChildFailure` are **not exported in U1** (their uses are U2: `PreRestart`, `FailedMessage`, restarts). The existing events (`receive-failed`, `prestart-failed`, `stop-accepted`) and their `detail` stay as they are today (raw recovered value); no existing test changes.
- **D4 budget.** `Budget{MaxRetries int32; Within time.Duration}` and `OneForOne[T](budget Budget, decide Decider[T]) Strategy[T]` are exported with the accepted stub signatures. In U1 the budget is **never consulted**, which is what Pekko does for Stop, Resume and Escalate: `requestRestartPermission` is reached only when `restart` is true (`FaultHandling.scala:673`). The conversions of S4 stay unexported and unimplemented until U2. Alternative (Owner may choose instead): export `OneForOne(decide)` now and change the signature in U2; this RULEBOOK does not recommend it (a signature break).
- **D5 interim.** As in section 0. A zero `Strategy[T]` from `SupervisorStrategy()` is treated as absent (A3). `AllForOne`, `DefaultStrategy` and `StoppingStrategy` are **not exported** (U6, U3). Top-level actors (no parent) stop directly (U5).
- **D6 initialization failures.** A `PreStart` failure (and a `PostStop` failure) keeps today's behavior under every parent: the decider is not consulted (A9a rows for init failures are U2/U4). Nothing in U1 touches `Spawn` creation failures.
- **D7 a parent that cannot take the Failed.** If the parent has accepted a stop or finished when the child fails, the child stops directly and no `Failed` is delivered. **Unknown** upstream equivalence (Pekko routes undeliverable system messages to dead letters, `ActorCell.scala:497-504`); this is a Go interim and is not asserted as parity.
- **D8 `makeDecider`.** U1 delivers the pair form (`FaultHandling.scala:276-283`: first matching pair wins, no match is `Escalate`) and the function adapter (`:285`). The trapExit form (`:260-262`) maps to `Restart` and so moves to **U2**. Pekko sorts pairs by class specificity; Go has no class hierarchy, so the Go form matches `errors.Is`/`errors.As` against the pairs **in declaration order** (a documented difference). Names are **Unknown in the ADR; PROPOSED**: the only pair type is `type CauseDirective struct{Cause error; Directive Directive}`; `MakeDecider[T any](pairs ...CauseDirective) Decider[T]` (match by `errors.Is`, in declaration order); and `DeciderFunc[T any](f func(ctx *Context[T], child Handle, cause error) (Directive, bool)) Decider[T]`. The function adapter keeps the full `Decider` arguments (context, failing child, cause) on purpose; upstream `:285` adapts a `PartialFunction` over the cause, and the Go adapter is deliberately wider so the context and child of rule 12 stay available. Names are PROPOSED; the Owner confirms or renames at approval.
- **D9 suspension model.** One suspension counter per cell; `Suspend` adds 1, `Resume` subtracts 1 and never goes below zero (`Mailbox.scala:148-170`, `:126-128`); a cell with a counter above zero processes no user message but still processes system items and an accepted stop. The failing cell adds 1 for itself and 1 to each child except the failing child of the `Failed` being handled (`dungeon/FaultHandling.scala:215-225`); the suspension of a child is recursive (`faultSuspend` 124-129). `Resume` is likewise recursive (`faultResume` 136-153, `Children.scala:216-222`).
- **D10 events.** U1 adds **no new event kind**. Names and payloads of `decision` events are Unknown and left to the units that need the judge (U3, U8).
- **D11 context expiry (A13).** ADR 0010 X1 says a `Context[T]` is valid only during its call and a later use is published as `ContextMisuse`. Whether the runtime already implements that for `Context[T]` is **Unknown**: no `ContextMisuse` appears in the non-test Go files of `pekko-actor` (checked with `rg -n -i misuse`). The decider receives a context valid only during the call. Test V11 asserts only what ADR 0010 X1 states and the runtime can show; if the expiry mechanism does not exist, the probe (RUNBOOK 5.1) reports it before the loop and the Owner decides between adding the minimal expiry to `actor.go` (writable) or moving the post-call half of V11 to `PORT-GAP(context-expiry)`. This is not decided by the implementer.
- **D12 test classification.** Portable, adapted, moved and omitted assertions are fixed in section 5 and are the Owner's by approving the hash.

## 2. Behavior specification (the implementer follows it; it is not open design)

Format: Source -> Observable -> Go adaptation.

1. **Failed message (A10).** Source: `Failed(child, cause, uid)` is a system message (`SystemMessage.scala:274-277`), sent by the failing actor to its parent in `handleInvokeFailure` (`dungeon/FaultHandling.scala:215-245`, the send at 233). Observable: the parent acts on it only for a currently known child whose `uid` matches; otherwise it drops it with a Debug log (`:305-325`). Go: an internal system item `failed{child ID, cause error}` of its own class; **not an item of the subject-keyed runtime lane** (`watch.go:218,238,280` would delete or drop it); the incarnation ID (`id.go`, unique per process) plays the role of `uid` (A10): the parent drops the item unless the ID is a currently registered child of the parent; a drop calls no decider, charges nothing and emits nothing new.
2. **Order.** Source: system messages are processed before user messages (`Mailbox.scala:230-236`; `processMailbox` runs `processAllSystemMessages` after each message, `:276`). Observable: the decision runs at the parent's next system-message boundary, ahead of its queued user messages. Go: the failed item is taken by the parent's `drain` before the next user pop; a decider call never overlaps a `Receive` of the parent.
3. **Stash.** Source: `Failed` is `StashWhenFailed`, so a suspended receiver stashes it (`SystemMessage.scala:220,274-277`, `ActorCell.scala:506-511`). Go: while the parent's counter is above zero its failed items wait and are handled, in order, after it is resumed to zero. (Stash while waiting for children is a restart concern: U2.)
4. **Suspension of the failing actor.** Source: `handleInvokeFailure` suspends itself, marks itself failed (or marks the child when the current message is a `Failed`), suspends its children except `skip` (`:215-225`). Go: when a `Receive` fails under a declaring parent, the cell adds 1 to its counter, adds 1 to each child except (when the parent is handling a `Failed`) the failing child of that `Failed`, emits `receive-failed` as today **without** `stop-accepted`, and sends the item. Siblings of the failing cell are never touched. **Skip rule:** the failing child of the `Failed` being handled is the skipped one in **every** failure of the parent that happens while it handles that `Failed` (escalate, invalid directive per rule 10, decider panic per rule 11), matching `handleInvokeFailure` (`dungeon/FaultHandling.scala:215-225`), which skips the child whenever the current message is a `Failed`; so that child's counter is never raised twice.
5. **Recursive suspension.** Source: `Suspend` -> `faultSuspend` = own +1 and `suspendChildren` (`:124-129`, `Children.scala:209-214`). Go: a suspend request on a cell adds 1 to it and requests it of every child, to any depth; the counter is balanced by one resume per suspend.
6. **Directive Resume.** Source: `handleFailure` -> `resumeChild` -> `child.resume(causedByFailure = cause)` (`FaultHandling.scala:366-391`, `:435-436`); `faultResume` takes the counter down by one, clears the failed mark if caused by failure, and resumes each child (with the cause only for the perpetrator) (`dungeon/FaultHandling.scala:136-153`, `Children.scala:216-222`). Observable: the failing actor and **its children** keep working (`SupervisorHierarchySpec.scala:815`); **siblings were never suspended and are not resumed** (the parent suspends nothing on Resume). Go: exactly that; the failed cell's counter and those of its descendants return to their values before the failure.
7. **Directive Stop.** Source: `processFailure(restart = false)` -> `context.stop(child)` (`FaultHandling.scala:666-677`). Go: `OneForOne` accepts a stop of the failing child (the existing `acceptStop`); a suspended cell still terminates (a stop is not stashed, as `Terminate` is not).
8. **Directive Escalate.** Source: `handleFailure` returns false and the parent does `throw f.cause` (`FaultHandling.scala:386-388`, `dungeon/FaultHandling.scala:314`; the throw is caught at `ActorCell.scala:533-534` and goes to `handleInvokeFailure`). Observable: the parent itself fails **with the same cause**, which its own parent's decider then sees with the parent as `child`. Go: the parent runs the failure path of rule 4 with the identical `error` value (`==`, not a copy), the escalated child counted as the skipped one (rule 4); under a no-strategy grandparent the parent stops directly (D5).
9. **Unmatched cause (A1).** Source: `applyOrElse(cause, escalateDefault)` (`FaultHandling.scala:372`, `:309`). Go: `ok == false` is Escalate, whatever directive is returned alongside, including the zero value.
10. **Invalid directive (A2).** Go-specific (D1, D2): with `ok == true`, a value not in `{Resume, Stop, Escalate}` (zero, 2, any above 4) fails the parent with `ErrInvalidDirective`, by the same failure path as a decider panic; nothing is applied to the child, which stays suspended and is therefore resolved by the grandparent's decision on the parent (rule 8 effects).
11. **Decider panic.** Source: a decider that throws fails the parent through the system-message catch (`ActorCell.scala:533-534`; `SupervisorSpec.scala:460-506`). Go: `recover` in the call; the parent fails with `*PanicError{Value}`; the child is untouched and not suspended again, as in rule 10 and the skip rule of rule 4. A `runtime.Goexit` in the decider is **not classified** in U1 (U3, `ErrGoexit`); the existing `abortGoexit` path must not regress and no test covers it.
12. **Decider context (A13).** Source: the decider runs inside the parent with `context` and `sender()` = the failing child (`dungeon/FaultHandling.scala:306`, `SupervisorMiscSpec.scala:165-180`). Go: the call is `decide(ctx, child, cause)`, `ctx` the parent's `*Context[T]` valid only during the call (D11), `child` a `Handle` with the failing child's ID. It offers what `Context` offers today (`Self`, `StopSelf`, `Stop`, `Child`, `Children`, `Parent`, spawn, watch).
13. **Strategy.** `Strategy[T]` is opaque and built only by `OneForOne`; `Supervisor[T]` is the optional interface of the parent (A3). The strategy is read when a failure arrives, from the parent's current actor.
14. **Out of the failing path.** Termination of children, `Watch`, `Terminated`, names, dead letters: unchanged.

Scenarios (V1-V4 trace to upstream; V5 onward are Go-side, derived from the source lines cited, **no Pekko run, no parity claimed**):

- V1 (`SupervisorHierarchySpec.scala:815`, ADAPTED) resume children after Resume: as the table row; also the failing `middle` Receive error is reported once.
- V2 (`:832`, ADAPTED) suspend children while failing: `slowResumer -> boss -> middle -> worker`; `boss` fails; while the `slowResumer` decider is held, the counters of `boss`, `middle`, `worker` are each 1 and a ping queued at `worker` is not received; after release, counters are 0 and the ping is answered once.
- V3 (`SupervisorMiscSpec.scala:165`, ADAPTED) the decider sees the failing child, as the table row; `Stop` terminated the child (`Done` closed).
- V4 Resume resumes the failing child and its descendants (recursive) and never touches siblings (rule 6; `Children.scala:209-222`): a sibling keeps processing messages during the decision and its counter is 0 throughout; the failing child's counter goes 1 -> 0 and so do its descendants'.
- V5 counted balance: two nested failures-and-Resumes in sequence leave every counter at 0; a counter never goes below 0 on a surplus resume (`Mailbox.scala:148-156`).
- V6 Stop (rule 7): the failing child's `Done` closes, its watcher gets exactly one `Terminated`, siblings keep working, messages still queued in the failing child are dead-lettered as on any stop.
- V7 Escalate (rule 8): `G -> P -> C`; `C` fails, `P`'s decider returns Escalate; `P` fails with the identical error value; `G`'s decider is called with `child` = `P` and that cause. `G` returns Resume: `P` and `C` both process messages again and all counters are 0 (`Children.scala:216-222` gives `C` the cause). `G` returns Stop: `P` and `C` terminate.
- V8 unmatched cause (rule 9, A1): `ok == false` (with the zero and with a valid directive) escalates exactly as V7.
- V9 decider panic (rule 11): `*PanicError` with the panic value; `G`'s decider sees `child` = parent and `errors.As` finds it; `errors.Is` through `Unwrap` finds an error panic value; the failed child of the panicking parent stays suspended until `G` resolves it; after `G` returns Resume, that child's suspension counter returns to its pre-failure value (0) and it processes a message again.
- V10 invalid directive (rule 10, A2): zero, `Directive(2)`, `Directive(5)` with `ok == true` each fail the parent with `ErrInvalidDirective` (`errors.Is`); each valid one is applied; `ok == false` with each of Resume, Stop, Escalate, `Directive(2)` and the zero value escalates; after the grandparent returns Resume, the failed child's suspension counter returns to its pre-failure value (0) and it processes a message again.
- V11 context (rule 12, A13): in the call `ctx.Self`, `ctx.Children()` (contains the failing child), reading `child.ID()` and `ctx.StopSelf()` work; use of the captured `ctx` after the call is checked as D11 allows.
- V12 stale Failed (rule 1, A10): after the child terminated (`Done`), an injected failed item for its ID calls no decider and changes no counter; after the same name is respawned, an item carrying the old ID is dropped and the new child is unaffected. (Injection uses the internal item type; "a grandchild failing while its parent restarts" is U2.)
- V13 order (rules 2, 3): with user messages queued at the parent, the failed item is decided before them; while the parent itself is suspended, a child's failed item is decided only after the parent is resumed.
- V14 interim (D5): a parent without strategy, and a parent returning a zero `Strategy[T]`: the child's `receive-failed` is followed by `stop-accepted` as today and no decider exists; a grandparent without strategy makes an escalating parent stop directly.
- V15 initialization (D6): a `PreStart` failure under a declaring parent calls no decider and keeps the existing event sequence.
- V16 `makeDecider` (D8): a listed cause -> its directive; an unlisted one -> `ok == false`; order of pairs decides; the function adapter passes through.
- V17 serial decisions: two children failing at the same time are decided one after the other, never concurrently, each exactly once (counted).
