## 1. Goal and non-goals
**Goal.** Expose the termination of the whole `System` in an ordered way: `Terminate()` accepts the stop of `/user` and hands the rest to the System's executor, and is idempotent; `WhenTerminated()` returns a channel closed when the root guardian finished, which happens after every descendant finished; `Shutdown(ctx)` is `Terminate` plus a wait bounded by `ctx`. Reject new top-level actors from the start of the termination. Let a running handler finish: nothing is interrupted.
**Non-goals (the scope guard).** This is the ordered termination of the `ActorSystem` and not `gracefulStop` of one actor, and not `CoordinatedShutdown`. It adds no phases, no hooks, no `registerOnTermination`, no external drain, no coordination with business or durable work, no cancellation of `PreStart`, handlers or `PostStop` (ADR 0008 `:125-127` is a separate, unimplemented extension), no cancellation of pending Asks and no new supervision strategy. **`Shutdown` promises nothing about journal writes, durability or draining mailboxes.** The persistence module is not widened by this unit.

## 2. What Pekko does (pin) and what it does not guarantee
- **Order [P].** `terminate()` (`A actor/ActorSystem.scala:1089-1104`) sets `terminating` and either runs `CoordinatedShutdown` or calls `finalTerminate()` (`:1112-1117`), which calls `guardian.stop()` on the user guardian. The system guardian watches the user guardian (`A actor/ActorRefProvider.scala:339`, wiring `:613-620`) and stops after its termination hooks (`:331-367`); the root guardian watches the system guardian, and the bubble-walker's `stop()` completes `terminationPromise` (`:448-461,476-485`). No order is coded other than this death-watch chain: **user, then system, then root**.
- **Idempotence [P].** `terminate()` has no CAS of its own; every call returns `whenTerminated` (`:1000-1002`, the `done` promise at `:1331`: the same future each time). The only CAS is inside `CoordinatedShutdown.run` (`A actor/CoordinatedShutdown.scala:720-723,782-784`). `isTerminating()` is `:1119-1121`. A test of two or concurrent `terminate()` calls: **no test found** (single calls only: `T actor/ActorSystemSpec.scala:226,254,278,303`).
- **Creation during and after [P].** `IllegalStateException("cannot create children while terminating or terminated")` (`A actor/dungeon/Children.scala:313-314`). `T actor/ActorSystemSpec.scala:300-326` asserts that once creation fails it keeps failing and that no created ref is left started; `:250-261` asserts `whenTerminated` carries `Terminated(rootGuardian)` with `addressTerminated` and `existenceConfirmed`, the same instance as `terminate()` returned; `:328-334` and `:359-375` assert the system ends when `/user` is killed or escalates.
- **A stopped guardian ends the system [P].** `ActorRefProvider.scala:616` ("chain death watchers so that killing guardian stops the application"); a `Failed` from a guardian reaches the bubble-walker (`:478-481`).
- **What the code does NOT show [P].** A durability guarantee; draining of mailboxes (`Mailbox.cleanUp`, `A dispatch/Mailbox.scala:340-354`, sends what is pending to dead letters); the completion of pending Asks when the whole system terminates (**sin verificar**: `PromiseActorRef.stop` completes with `ActorKilledException("Stopped")`, `A pattern/AskSupport.scala:653-676`, but nothing in the termination path walks the temporary refs; an Ask to an already-terminated recipient fails at once, `:312-318,373-375`); all-or-nothing between phases. Terminating before the guardians processed a first message: **sin verificar** (no code handles it specially). Messages to the system after `whenTerminated` completed: **sin verificar**, no test found. `awaitTermination` does not exist in this tree.
- **`gracefulStop` is another thing [P].** It acts on one actor with a stop message and a watch, and a timeout fails the future with `AskTimeoutException` without stopping anything (`A pattern/GracefulStopSupport.scala:59-69`; `T pattern/PatternSpec.scala:38-56`). `CoordinatedShutdown` runs registered phases and calls `finalTerminate()` at its last one (`A actor/CoordinatedShutdown.scala:266`).

## 4. Decisions (the Owner's, as recorded in the request; D6 to D9 are mine)
How I read the request: it arrived partly unreadable (section 11). Where the reading is mine it says so.
- **D1 API (decided by the request).** Three exported methods on `*System`, no other exported identifier except `ErrSystemStopping`:
  - `Terminate()`: idempotent and safe from any goroutine. It accepts the stop of `/user` (`System.Stop` on the internal handle) and returns; the stop is carried out by the System's executor exactly as for `System.Stop` (D10). **It does not itself start a goroutine and it does not wait for the termination.** Where the cascade runs (another goroutine, or the caller) is the executor's choice (D10).
  - `WhenTerminated() <-chan struct{}`: returns, on every call, the same channel (the root guardian's `done`); it only returns the channel and starts nothing. The channel is closed by `finalize` of the root guardian, on whichever goroutine the executor runs that finalization; it is not closed by a goroutine of `WhenTerminated` or `Shutdown`.
  - `Shutdown(ctx context.Context) error`: calls `Terminate`, then waits for the channel or for `ctx`.
- **D2 Context of `Shutdown` and errors (decided; corrected after the first draft).** `Shutdown` first calls `Terminate`, so the termination starts even if `ctx` is already cancelled. The context bounds **only the wait**. **Finalization has priority over cancellation:** if the channel of `WhenTerminated` is closed (already, or when the wait ends) it returns nil, also with a cancelled or expired `ctx`; because a Go `select` picks at random when both are ready, on `ctx.Done()` it does a non-blocking receive on the channel first and returns nil if it is closed. Otherwise it returns **`ctx.Err()` itself**, unwrapped, with no package error (`ErrShutdownDeadline` does not exist): `context.Canceled` or `context.DeadlineExceeded`. It **never claims the system terminated** when it returns an error (ADR 0008 `:125`); the termination continues and no handler or hook is interrupted. `ErrSystemStopping`: returned by a top-level `Spawn` once `/user` is stopping; `errors.Is(ErrSystemStopping, ErrParentStopping)` is true, so no existing check breaks. A `Spawn` from a `Context` keeps returning `ErrParentStopping`.
- **D3 `WhenTerminated` (decided).** No new strategy and no new guardian behavior. The closing of the channel is the closing of `root`'s `done`, which `finalize` performs only after `root`'s descendants finished (so: every descendant of `/user` and `/system`). A test verifies it with a real tree (section 7).
- **D4 Observable signal (decided; refined).** The same channel across calls. `Terminate`, `WhenTerminated` and `Shutdown` contain **no `go` statement and start no observer or helper goroutine**; `Shutdown` waits with a `select` in the caller's goroutine. This is a claim about the code of the three functions, **not** about the whole process: with the default executor `Terminate` makes the runtime run the `/user` drain on a new goroutine (`executor.go:19-21`, `goroutineExecutor.Execute` is `go f()`), exactly as `System.Stop(/user)` does today, and that goroutine is not new behavior. The distinction (own helper goroutine: none; goroutine started by the executor for the activation: yes, by default) is stated in the doc comments.
- **D5 Messages and Asks (decided).** A send to a stopped actor remains a dead letter, once; the pending messages of a stopping actor are dead-lettered by `finalize`, as today. Pending Asks keep their own deadline or context and are not cancelled by `Shutdown` (AK17 is resolved as "not guaranteed", coherent with Pekko, which does not show otherwise); an Ask against a terminated target returns `ErrRecipientTerminated`. `Shutdown` promises nothing about messages, ADR 0015 or otherwise.
- **D6 `Shutdown` from a handler or a hook (decided; corrected).** The termination of an actor waits for its running handler or hook (`Receive`, `PreStart`, `PostStop`, `OnTerminated`) to return and runs no hook concurrently. So `Shutdown(ctx)` called from inside any of them **cannot see the system terminate until that handler or hook returns**, and ends by `ctx` with `ctx.Err()`. `Terminate()` is valid from any of them: with the default executor it returns after handing the drain over; **with an inline executor (test only, D10) it runs the cascade in the caller and so cannot return while a hook of that cascade is held**. **No automatic detection or rejection is introduced**; the behavior is documented in the doc comments and tested (SH7, SH11).
- **D7 No state, no change to the guardians (mine).** No stopping flag is added to `System`; "the system is stopping" is the closed gate of `/user`. `guardian.go`, `stop.go`, `cell.go`, `hierarchy.go` and `ref.go` are not edited.
- **D10 The executor and `Terminate` (decided after finding the incompatibility; no behavior change).** `acceptStop` hands the activation to the System's executor (`c.sys.exec.Execute(c.drain)`, `stop.go:59`), and every later step of the cascade (the child stops, `PostStop`, `finalize`, the watchers' callbacks) is also scheduled through it (`stop.go:137`, `hierarchy.go:174`, `watch.go:249`). The executor is not user-configurable: it is the unexported test seam `options.exec` (`system.go:27`), `Config` has no executor field and `NewSystem` always uses `goroutineExecutor` (one goroutine per activation, never inline; `executor.go:15-21`). Consequences, stated in the contract and not changed: (a) for every `System` a user can build, `Terminate` returns once the stop is accepted and the drain is handed to a new goroutine; (b) under an **inline** executor (internal tests only) `Terminate` runs the drain, and with it the termination cascade, hooks and callbacks, **in the caller's goroutine**, so a hook held by the test can hold `Terminate` (and `Shutdown`, whose wait starts only after `Terminate` returns, so its `ctx` cannot bound it); (c) under a **deferred** executor nothing runs until the test drains it. `Terminate` is documented as "accepts the stop and hands it to the executor", never as "does not run user code". No change to `stop.go` or to the executor is made.
- **D11 Text of `ErrSystemStopping` (text only; no behavior change).** `Error()` is exactly `actor: system is stopping`. `errors.Is(err, ErrParentStopping)` is true for it (for example `Unwrap` returns `ErrParentStopping`), and `errors.Is(spawnErr, ErrSystemStopping)` is true for the error a top-level `Spawn` returns. The text is a proposal the Owner may change; changing it changes no behavior.
- **D8 Tests and gates (mine).** Deterministic tests on the controlled executor for the cascade and the interleavings; proportional gates (section 9). The implementer's only test command is the wrapper `run-shutdown-tests.sh` (`-run Shutdown`, `-race`, once).
- **D9 The judge (decided).** No judge scenario is added and **the judge is not run** (no `run-go.sh`, no `mutate_go.py` campaign, no judge self-test), see section 9.

## 6. Invariants
- **I1 Order, as verified relations and not a total order (corrected).** (R1) `root` finalizes after `/user` and after `/system`, whatever started the termination, because both are its children (ADR 0014 rule: a parent's `PostStop` runs after every descendant finished); this is what makes `WhenTerminated` safe. (R2) Each guardian's `PostStop` runs after all of its own descendants'. (R3) When the termination starts at `/user` (`Terminate`, a `Stop(/user)`, or the failure or escalation of `/user`), `/system` finalizes after `/user` and `root` after `/system`, because `/system` stops on `Terminated(/user)` and `root` on `Terminated(/system)`. (R3) is **not** claimed when a guardian's stop was already started by another cause (for example a direct `Stop(/system)` or `Stop(root)` through the test seam, or a `Terminated` that reaches a guardian already stopping): then only R1 and R2 hold, and the order between `/user` and `/system` is not promised. No relation between a guardian's `Terminated` delivery and a `Done` closing is claimed. Observed through the existing `guards.terminated` hook and the `PostStop` order.
- **I2 Finalization.** `WhenTerminated()` is closed if and only if `root`'s `done` is; never before every descendant ran its `PostStop`.
- **I3 Idempotence.** Any number of `Terminate`/`Shutdown` calls, concurrent or not, before or after the first activation, stop each guardian once (one `stop-accepted` per guardian) and return normally.
- **I4 Spawn.** From the first `Terminate`, a top-level `Spawn` returns `ErrSystemStopping` (which is-a `ErrParentStopping`), or, if it won the race, commits and is stopped; never a leaked running actor.
- **I5 Handlers and hooks.** Nothing is interrupted; hooks never overlap; on a blocked handler or hook `Shutdown(ctx)` ends by `ctx` with `ctx.Err()` and the termination goes on and completes when the handler returns. `Terminate()` returns once the stop of `/user` is accepted and handed to the executor: promptly with the default executor, **not necessarily with an inline one** (D10).
- **I6 Messages.** A queued message at a stop is a dead letter and is not received; a send after the stop is a dead letter once.
- **I7 Asks.** Unchanged (D5).
- **I8 No promise.** `Shutdown` documents no guarantee about journal writes, durability or draining.
- **I9 No helper goroutine** (D4): the three functions contain no `go` statement and call nothing that starts one except through the System's executor (the same path as `System.Stop`); checked by the coordinator's readback and by the review, not by a goroutine count (D4, SH8).

I read it as: prepare the RULEBOOK and execution package, reusing #192 for the design and #193 for the implementation, with no new issue, no agent run, no tag, no native review, no widening to Persistence or `CoordinatedShutdown`; API as D1; context and errors as D2; `WhenTerminated` as D3; the observable signal without an observer goroutine as D4; Tell, dead letters and pending Asks as D5; the scope guard of section 1; verify the existing wiring for every executor order, including a `Stop` before activation, and stop the package if the runtime shows an incompatibility; deterministic cascade tests, proportional gates, no minimal judge scenario and no judge run; include the correction of the stale U9 text in ADR 0017 in the package PR; budget with an evaluation stop at 450,000 and a ceiling of 560,000 that do not authorize execution; a final report with the differences from Pekko, pending decisions, surfaces, budget and an authorization request. Where the text was unreadable I kept the narrower reading.
Not decided here (for the Owner): whether the proposed text of `ErrSystemStopping` (D11) stays; whether a Go campaign is run later; the behavior of the dead-letter hub after the termination (unchanged: it keeps publishing; Pekko: sin verificar).

**Second round (corrections before authorization).** The correction request was also partly unreadable (it arrived compressed). I read it as: (1) remove `ErrShutdownDeadline` from the package and return `ctx.Err()` unwrapped (D2); (2) `Shutdown` from a handler or hook cannot finish before that handler or hook returns, `Terminate()` is valid everywhere, and no automatic detection or rejection is introduced (D6, SH7); (3) finalization has priority over cancellation, including when both are ready together (D2, SH6); (4) I1 as verified relations, not a total order, since a guardian may be stopping for another cause when its `Terminated` arrives (I1, SH1, SH10); (5) SH4 tests the listed executor orders, including a deferred and an inline executor, and does not prove every interleaving; (6) SH8 does not use `runtime.NumGoroutine`; the absence of a goroutine is checked by readback and review (SH8, MS7); (7) the differences from Pekko mark which are goPekko decisions (section 12). The ADR 0017 correction and the rest are unchanged.

**Third round (found before running).** The package was found incompatible with the runtime in one claim, before any run: `Terminate` was described as non-blocking and without goroutines, but `acceptStop` hands the drain to `exec.Execute` (`stop.go:59`), so an inline executor runs the cascade in the caller and a held hook can hold `Terminate`. The request, partly unreadable, was read as: keep the minimum (`Stop(/user)`, no helper goroutine), describe `Terminate` and `WhenTerminated` explicitly in terms of the executor, distinguish an inline executor, say that a goroutine count cannot be a deterministic test, fix the text of `ErrSystemStopping` with its `errors.Is(err, ErrParentStopping)` relation, and change no behavior (D10, D11, I5, I9, SH7, SH8, SH11).

## 12. Differences from Pekko (declared; **P** = Pekko behavior, **G** = a goPekko decision that is not in Pekko)
- **[P, not ported]** `CoordinatedShutdown`, phases, `registerOnTermination`, termination hooks, `exit-jvm` and `isTerminating()` are not provided. **[G]** that is a scope decision, not a Pekko property.
- **[G]** `terminate()` returning a `Future` becomes `Terminate()` (no return value) plus a channel that closes; `Shutdown(ctx)` has no Pekko counterpart and its priority of finalization over cancellation is a Go decision.
- **[G]** `Terminated(rootGuardian)` is not delivered; the channel carries no value, no `addressTerminated` and no `existenceConfirmed`.
- **[G]** Creation after the start of the termination returns `ErrSystemStopping` (is-a `ErrParentStopping`) instead of `IllegalStateException`; Pekko's "once it fails it keeps failing" (`ActorSystemSpec.scala:300-326`) is tested in SH5 and is **[P]**.
- **[P, whole-system case sin verificar]** Pending Asks are not completed by the termination, which is what the Pekko code shows; in goPekko it is also a decision **[G]** (no registry, ADR 0015 D7).
- **[G]** A `Terminate` before the first activation of the guardians runs `PreStart` once and `PostStop` once (ADR 0012); Pekko's behavior is **sin verificar**.
- **[G]** `Shutdown` from a handler or hook can only end by `ctx` and no automatic rejection exists; Pekko has no `Shutdown`.
- **[G]** `Terminate` hands the termination to the System's executor and, under an injected inline executor (tests only), runs it in the caller; Pekko's `terminate()` calls `guardian.stop()` (a system message) and has no pluggable executor at this point (`ActorSystem.scala:1112-1117`).
- **[G]** R3 of I1 is claimed only when the termination starts at `/user`; Pekko codes no order other than the death-watch chain (`ActorRefProvider.scala:613-620`).
