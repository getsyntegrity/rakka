## 4. Result: M66 is NOT detected. outcome `timeout`, 30 of 30 runs, no violation provable
Row of `judge/mutation-report.tsv`: `M66 S22 concurrent pekko runs=30 pass=0 fail=0 harness_error=0 timeout=30 outcome=timeout fired_rules=(none) expected_rules=G5.f expected_hit=false`, note "no end after 10000 ms (deadline 10000 ms); no violation is provable from the prefix". It is not a detection and is not counted as one; the classification was not touched. The checker says so: `uncaught M66: timeout`, `pending G5.f: M66 timeout`, Pekko implemented mutations detected 31/32, clauses observed 30/31 with one unknown (`G5.f`).

Why (read from a kept log, `S22.concurrent.r1.jsonl`, and from the code, not assumed):
- M66 does what it was designed to do on the real path. In run 1 `c` shows one `pre-restart` (t=17) and **one** `post-stop` (t=19, the P1 of the default `preRestart`); both children then run their `post-stop` (t=35, t=38) and the watcher gets `terminated` (t=39). The second `post-stop` of `c` (P2, `finishTerminate`) never happens.
- But the Pekko S22 declares its own completion predicate (`judge/pekko-harness/Judge.scala:479`): the run ends only when there is at least one `terminated` AND at least two `post-stop` of `c`. The skipped P2 is exactly what the run waits for, so it never completes and ends on the 10 s deadline.
- The comparator judges `G5.f` as follows (`judge/comparator.py:291-299`): on a complete log each count must be exact, zero included; **on a prefix a count only fails once it is already exceeded**. A timeout run is a prefix, so a *missing* second `post-stop` (count 1 < 2) is not provable from it.
Consequence, stated plainly: with S22 as it is, no Pekko mutation that suppresses the second `PostStop` can ever be `failed`; its harness cannot finish without it. The Go side differs only in that its harness ends on the observed `Terminated` (that is why GMdefaultps is detected there). This is a property of the approved design of S22 (U7), not a defect found in M66 and not something this unit changes: the brief forbids weakening the scenario, the comparator or the classifications.

## 5. Limits and what remains open
- The brief's goal ("a mutation that breaks the second `PostStop` ... S22 detects it by `G5.f`") is **not met** by M66. `G5.f` stays without an observed Pekko detection.
- Options for the Owner (a second design is a semantic decision, not taken here): (A) a mutation that makes the old instance receive an EXTRA `postStop` (a third one, for instance by calling `aroundPostStop` in `finishTerminate` also when the restart was waiting); a count of 3 is already "exceeded" on a prefix and on a complete log, S22's predicate is satisfied, so `G5.f` fires. It breaks the clause by excess, not by omission; (B) accept the limitation: M66 stays as documented evidence of an undetectable-by-design omission and `G5.f` stays unobserved on Pekko; (C) change the S22 completion predicate or the clause on prefixes: it weakens or changes the scenario/comparator, which the brief forbids, so only on an explicit Owner decision.
- No Go change: `pekko-actor/`, `judge/mutate_go.py`, `judge/go-mutation-report.tsv` and the Go scope are byte-identical, so the Go campaign was not repeated and the checker still reports CURRENT 18/18 and benign 1/1.
- darwin/arm64, one run of 30; JDK 11 for sbt and JDK 8 for the harness; not Linux; not a calibration.
