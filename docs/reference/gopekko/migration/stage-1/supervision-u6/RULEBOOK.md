## 2. Public API (exact)
Added to `pekko-actor/actor/supervision.go`, next to `OneForOne`, with a doc comment that states the semantics of section 3, **the order note of section 5 ("ascending name, as observed in Pekko v1.7.1, not a guaranteed contract")**, the snapshot-before-decider rule and the decider-spawn consequence of section 4, and that the Java-API overloads, `loggingEnabled` and strategy equality are absent:

```go
// AllForOne is the strategy of Pekko's AllForOneStrategy: a Restart or a Stop decided for one child applies to all
// the children of the parent.
func AllForOne[T any](budget Budget, decide Decider[T]) Strategy[T]
```

- Same parameters, zero values and nil-decider rule as `OneForOne`: `Budget{}` denies every restart; a nil `decide`, or a decider that returns `ok == false`, escalates every failure. `Budget{MaxRetries: -1, Within: -1}` is the unlimited budget of Pekko's defaults.
- It returns the existing type `Strategy[T]`. No new exported type, field, option or constant. The unexported `kind` gains `kindAllForOne`. The zero `Strategy` keeps meaning "no strategy" (`DefaultStrategy`, A3). A parent declares it through the existing `Supervisor[T]` interface.
- `OneForOne`, `DefaultStrategy`, `Budget`, `Decider`, `Directive`, `MakeDecider`, `MakeRestartDecider`, `DeciderFunc`, `GuardianStrategy` and its constructors are **unchanged**. `GuardianOneForOne` stays the only guardian constructor (section 8).
- **Adapted, not ported (declared):** the Java-API constructor overloads (`FaultHandling.scala:479-542`) have no Go equivalent, because `Budget` plus a `Decider` (or `MakeDecider`) already cover them; `loggingEnabled` is U9; equality of strategies does not exist in Go.
- A8 of ADR 0017 stays: user-defined strategies are #450 item 1, not this unit.

## 3. Semantics
Let P be the parent, F the failing child, `decide` the decider, `S` the set of section 4.

| Rule | Behavior | Evidence |
|---|---|---|
| R1 Decider | consulted once per `Failed` item, exactly as for `OneForOne`, with the failing child's handle and cause. A panic or Goexit of the decider follows the existing path (`failParent`, then `failUp`): **AllForOne itself takes no action** (no counter is charged, no sibling is restarted, stopped or resumed, no `restart-denied`), but P has failed, and the **propagation of P's failure** (R3a) applies | `FaultHandling.scala:366-390`; Go `supervision_failure.go:218-232,248-290` |
| R2 Resume | applies to F only (`resumeFrom(cause)`). Siblings are not suspended, resumed or restarted. Identical to `OneForOne` | `:374-377` (the code, not the docs) |
| R3 Escalate (`Escalate`, `ok == false`, nil decider) | P fails with the cause through the existing `failParent`; **`processFailure` does not run: AllForOne takes no action: no counter is charged, no sibling is restarted or stopped by this strategy.** Identical to `OneForOne` | `:386-388`; this is why `SupervisorHierarchySpec:767` is not an AllForOne test |
| R3a Propagation of P's failure (any path where P fails: R1 panic/Goexit, R3, `ErrInvalidDirective`) | **Not an AllForOne action and not a requirement of "intact siblings".** P suspends itself and all its children **except F** (+1 each, recursive), then reports to its own parent. F keeps only the +1 of its own failure. What happens to the siblings next is decided by P's parent: Resume of P resumes them (net 0, no hook); Restart of P restarts them as survivors (U2); Stop of P stops them. Tests assert "no AllForOne action" and the propagation count together, never "siblings untouched" | `dungeon/FaultHandling.scala:215-245`; Go `supervision_failure.go:218-232` |
| R4 Stop | **every** child of `S` is stopped (F included), each as a `context.stop(child)`: the existing `noteStopID` then `acceptStop(nil)`. No budget is consulted, no counter changes | `:565` |
| R5 Restart, all permitted | the permission of **each** child of `S` is requested **in the order of section 5**, with the strategy's `Budget`, through the existing `statsFor(node, id).requestPermission(budget, nanotime)`. | R6 Restart, one denies | the evaluation **short-circuits** at the first denial: the counters of the children before it stay advanced (they were charged), the denier's counter is whatever `requestPermission` left, **the counters of the children not reached are untouched**. No child was suspended by the strategy before the decision, so there is nothing to undo | `forall` short-circuit; `:564-566` |
| R7 A child that cannot be restarted (not `restartable`) | counts as a denial without being charged, as in `applyRestart` today (`ok && requestPermission(...)`) | `supervision_restart.go:176-186` |
| R8 Hooks | each restarted child runs the existing path: `PreRestart(cause)` on the old instance (default: stop its children, then `PostStop`), factory, `PostRestart(cause)`. A **healthy sibling has none** (its last `Receive` succeeded, or it never received one: absent). ## 4. The set S, children that end or appear (D1, D2 CORRECTED)
- **D1 (corrected): one snapshot of the committed children of P, taken before the decider runs** (in `handleFailed`, after `strategy()` returns and before `st.decide`, and only when the strategy kind is `kindAllForOne`). It **includes children whose stop was already requested** (Pekko's `stats` view includes `toDie`; `hierarchy.go:survivors(n)` returns them ascending by name, and `childByID` includes stopping children; the implementer confirms that `survivors` includes them and, if it does not, reports `BLOCKED(surface): hierarchy.go` with the evidence). The same snapshot serves the permission phase and the application phase; no second read. The snapshot is a value (a slice of records taken once), the Go counterpart of the immutable `TreeMap` the upstream view wraps: later spawns and terminations do not change it. Upstream evidence: section 1 (container, `getAllChildStats` evaluated as an argument at `dungeon/FaultHandling.scala:313`).
- **Cost:** the snapshot is taken for every failure handled under `AllForOne`, including ones the decider resolves with Resume or Escalate, because Pekko's capture is also unconditional and a conditional capture after the decider would be the divergence. `OneForOne` takes none.
- A child that already finished before the snapshot is not in `S`: not charged, not restarted.
- **A child in `S` that ends between the snapshot and its turn (during the decider, or during the permission or application phase) stays in `S` with the counters captured with it (corrected: the earlier draft skipped it, which changes the outcome).** Pekko keeps the captured view, charges that child's `ChildRestartStats` and lets it deny: if its counter would deny, the round is a denial and the whole captured set is stopped; if it permits, the round restarts the others. Skipping it could turn a Pekko denial into a global restart. **Go mechanism:** the snapshot records, for every member, its record **and its `*restartStats` pointer, both taken in one critical section under `System.mu`** (inline the get-or-create of `statsFor`, which locks separately; calling `statsFor` per child after the snapshot would race with `forgetChildLocked` and re-create an entry for a completed child). The helper lives in `supervision_restart.go` (no `hierarchy.go` edit). `forgetChildLocked` deletes the map entry (`hierarchy.go:230`), not the captured pointer, which is the counterpart of upstream's immutable view. The permission phase evaluates the captured pointers of **all** members in name order whether or not a member is still alive; it never calls `statsFor` again, so no entry reappears in `n.stats`.
- **Application to a member that has finished:** nothing is observable and nothing may leak, as in Pekko where the restart or stop lands on a dead ref. A Stop or a denial on it is harmless (`noteStopID` ignores an ID not in `n.out`, `hierarchy.go:251-253`; `acceptStop` on a finished record is a no-op). A restart (`suspend()` then `recreate`) on it must leave no suspension, hold or counter behind and must not block a later restart of P; for a member that is registered but terminating, the restart request must leave the counters balanced (upstream `faultRecreate` else-branch). If the existing cell code cannot guarantee either without touching `cell.go`, the implementer reports `BLOCKED(surface): cell.go` with the failing test and does not edit `cell.go` (judge anchors). No liveness check is used to skip a member in the permission phase.
- **D2 (corrected): a child created during the round is outside it.** The Go decider receives a `*Context[T]` (Pekko's has none), so it could `Spawn` a child; because the snapshot precedes the decider, that child is **not** in `S`: it is never charged, never restarted, and **is not stopped** by a Stop or a denial of this round (as in Pekko, where it is absent from the captured view). It starts like any child committed under P (existing `inherit`: if P holds pending suspensions it inherits that count). If the same decision is Escalate or P otherwise fails, it is suspended with P's other children by R3a, as any child would be. A child created by any other path after the snapshot (a concurrent `Spawn` from P's own code cannot overlap, since the round runs inside P's activation) is treated the same way. Documented in the `AllForOne` doc comment; pinned by AF16.
- A child with a pending `Failed` item of its own (it failed before its sibling's round was decided) is not special-cased: its item is handled later as any other (Pekko drops only on a UID mismatch, and a restart keeps the UID). It is a member of `S` for the current round, restarts with F's cause and **keeps its own failing message** (R8). Its own suspension from its failure (+1) is released only when its own item is handled, so after the first round it is still suspended by that +1. Pinned by AF14b; no change to the stale-ID rule of `handleFailed`.

## 5. Evaluation order (D3 CORRECTED: observed behavior of v1.7.1, not a public guarantee)
- **Observed in Pekko v1.7.1:** the children container is an immutable `TreeMap[String, ChildStats]` keyed by child name, and the `stats` view iterates `valuesIterator` of that map (`dungeon/ChildrenContainer.scala:62-66,79,120,174`). Iteration is therefore **ascending by name** under `Ordering[String]` (the natural `String` ordering, UTF-16 code units). `children.forall` and `children.foreach` at `FaultHandling.scala:554-567` follow it, and so does `finishRecreate`'s survivor snapshot.
- **Go equivalence:** child names are validated as ASCII (`names.go:9-24`, ActorPath rules), where UTF-16 order equals byte order, and `hierarchy.go:287-288` already documents `survivors` as the TreeMap order. The Go order is the same: **ascending child name, bytewise**. F has no priority. The short-circuit of R6 depends on names, and the tests name children accordingly. Restart requests (R5) are issued in the same order after all permissions are granted.
- **Not a public guarantee:** no Pekko documentation, signature or test promises this order. `AllForOneStrategy`'s scaladoc says nothing about it, and `processFailure` receives `children` typed as an `Iterable` described as "a lazy collection (a view)" (`FaultHandling.scala:364`). It is an implementation property of the pinned version. The Go `AllForOne` doc comment says: "children are evaluated in ascending name order, as observed in Pekko v1.7.1; this is not a guaranteed contract". The tests pin it as **observed behavior to detect an unintended change**, not as a promise, and a future Pekko pin change must re-verify it. The earlier wording of this RULEBOOK ("not specified, an adaptation") and the exploration report it relied on were wrong about the container type; this section replaces them.

## 6. Interaction with the other layers
- **Initialization failure.** A child whose factory or `PreStart` fails reaches the decider as `*InitializationError` (U2/U4). Under `AllForOne` a permitted Restart restarts all of `S`, F through its existing create path (`recreate` of a never-initialized cell is a Create); a denial stops all. Pinned by AF18.
- **Hooks of the parent.** `PreRestart`/`PostRestart` of P are not involved. A restart of P (from an escalation) restarts its children through the existing survivor path, not through this strategy.
- **Death pact and `OnTerminated` failures** reach the decider as today (U3); nothing changes.
- **Top-level actors** are children of `/user`, whose strategy comes from `Config.GuardianStrategy` (OneForOne only). `AllForOne` is for actors that implement `Supervisor[T]`.

## 8. Guardian
`GuardianOneForOne` and `StoppingGuardianStrategy` are unchanged. A guardian `AllForOne` would make the failure of one top-level actor restart all the others; that is neither requested by #447 nor Pekko's guardian behavior, and it is not offered.
