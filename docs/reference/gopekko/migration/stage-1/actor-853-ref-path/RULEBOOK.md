**Fields compared today.** `idHandle{id ID; sys *System; done <-chan struct{}}`: `==` is "same ID, same `*System`, same done channel". The `ActorPath` type is a struct of an `Address` (two strings) and a string (`actor_path.go`: "no slice, pointer or exported field, so == is the equality"), so it is comparable and adds no panic to interface comparison.

**Proof that adding `path ActorPath` to `idHandle` changes neither identity nor equality of any handle that is compared or keyed:**

1. `path` is a pure function of the cell: written once in the literal, never rewritten. Two `identity()` values of one cell carry the same `path`; two cells already differ in `id`. So among `identity()`-built values, `==` is true before iff true after.
2. An ID-only handle (`watch.go:542`, `supervision_failure.go:252`) has a nil `done` and a zero `path`; an `identity()` value has a non-nil `done` (`commitCell` makes one per cell) and a non-zero `path`. They already differ by `done` today and differ after. Two ID-only handles with the same `id` and `sys` are equal before and equal after (both zero path).
3. The only construction whose equality could flip is a hand-built `idHandle` with the same `id`, `sys` and `done` as a cell's `identity()` and no path: equal before, unequal after. It is constructible only inside the package's tests; the one test row that supplies a cell's `done` (`registry_retention_internal_test.go:237`) uses another System (`sys: other.sys`), so it was already unequal to `a.identity()`, and no test or code compares or keys it. So no compared or keyed `idHandle` changes. This is the residual edge; it is disclosed, pinned by an equality test in `ref_path_internal_test.go` (identity twice equal; ID-only unequal to identity; ID-only equal to ID-only) and compared base versus change in the differential check.

**Public identity versus structural equality.** The public API identifies a handle by `Handle.ID()`; `Watch`, `Unwatch`, `System.Stop` and `System.Done` resolve a handle by `ID()` (or its terminal state) alone (`hierarchy.go` `idHandle` comment). `==` on the unexported `idHandle` struct is a different thing: structural equality of `id`, `sys` and `done` (and, after the change, `path`). This unit changes the public identity not at all and the structural equality in the one edge of point 3. **Production consumers of the previous structural equality:** `git grep -nE '[^=!<>:](==|!=)[^=]'` over non-test `pekko-actor/**/*.go` and `pekko-actor-typed/**/*.go` at `db614b87` gives 215 raw lines, 198 once comment-only lines are dropped (`grep -vE '^[^:]+:[0-9]+:\s*//'`); filtered for handle-like operands only `supervision_restart.go:239` (`m.rec.id() != f.child`, IDs), `system.go:215` (`th.owner() == s`, `*System`) and `watch.go:58` (IDs) remain; `hierarchy.go:167` compares `e.rec == r` (record pointers, `*cell`); `watch.go:160` (`sameMessage`) compares user message values and would see an `idHandle` only if a user `T` embeds one. The type assertions to the handle types are `ask_endpoint.go:134`, `ref.go:55` (`*ref[T]`), `system.go:215` and `watch.go:132` (interfaces): none compares. **None found by this grep** depends on `idHandle` structural equality; this is a finding of that grep, not a claim of universal equivalence for code outside it (users of the exported API can compare handles and key maps by them: for `identity()` values of one cell that stays true).

**Result:** no comparison or keyed use depends on a handle's path; adding it changes neither identity nor equality of any compared or keyed `idHandle`. **STOP condition (b) did not fire.** The alternative the Owner asked to be ready (not applied): keep `idHandle` unchanged and have `PathOf` resolve an `idHandle` through the registry by `ID`; rejected because a retired non-guardian `idHandle` would then report false (it still carries its `done`), which loses P7 for handles taken before termination.

## 7. Condition (c): invariance of the accepted names, the System address, the parent path, and the defensive failure
**Names accepted by `Spawn`.** `validChildName(s)` is `s != "" && s[0] != '$' && validPathElement(s)` (`names.go:26-33`). `ActorPath.Child` runs `checkPathElement` (`actor_path.go`), which fails for an empty element, an element with `/`, an element with `#`, or `!validPathElement`. A name accepted by `validChildName` is non-empty and passes `validPathElement`; the characters `validPathElement` accepts are letters, digits, `validSymbols = "-_.*$+:@&=,!~';"` and `%XX` with two hex digits, which contain neither `/` nor `#`. So `Child` cannot fail for any accepted name. The root guardian's name `""` is never passed to `Child`: its path is `NewRootPath(address)`.

**Generated names.** `generateName` returns `"$"` followed by characters of `base64Chars` (letters, digits, `+`, `~`), all inside the set above; the name is non-empty and has no `/` or `#`, so `Child` accepts it (`$` is accepted by `validPathElement`; only `validChildName` rejects a leading `$`). The counter is a `uint64` and every value yields at least one character.

**System address.** `newSystem` sets `address = Address{protocol: LocalProtocol, system: name}` with `name = Config.Name` or `"default"` when empty (`system.go:150-154`, `defaultSystemName`), so both parts are non-empty and `NewRootPath` (which rejects only the zero Address) cannot fail. `System.Address` is documented "never the zero Address" (`system.go`). The address is set once and never written again.

**Parent path.** `spawnTarget.parent` is `s.guards.user` for a `System`, `x.c.identity()` for a `Context`, `root.identity()` for the two guardians below the root, and nil only for the root guardian. Each of these is the `identity()` of a cell built by `commitCell`, which sets a non-zero path (the root path or a `Child` of a non-zero path), by induction from the root guardian. A `Context` is valid only inside its own actor's handler, so its cell was committed. Therefore the parent path of every spawn is non-zero.

**Test (P11), written first:** a table over the explicit valid names (letters, digits, every `validSymbols` character, `%41`, a long name), over `generateName` values for the first 4096 counters (every value up to and across the 1-, 2- and 3-character boundaries: 63, 64, 4095, 4096) and over the default and a given `Config.Name`; each must yield a non-zero path equal to `parentPath.Child(name)`, and the parent path of a top-level spawn is the `/user` path.

**Defensive failure: the chosen treatment.** `spawnTarget.childPath(name)` (documented as an internal invariant: never a zero path for a valid actor) returns the path or **panics with an internal-invariant error before anything is reserved**.

Evidence that this is the treatment consistent with the current code, and that it changes no contract:

1. `Spawn` documents its error set as exactly three errors plus `ErrInvalidMailboxCapacity`, and "After the child is committed nothing in Spawn can fail" (`spawn.go:60-68`). Returning an explicit error from `commitCell` for a failed path would add a fifth error to a documented set, for a case that cannot happen for any value `Spawn` accepts: that is a contract change, so it was not chosen (STOP condition (c) names it).
2. `newGuardian` already treats an unreachable `commitCell` error as an internal invariant: `panic(err) // unreachable: fresh nodes, open gates, valid names` (`guardian.go:124-126`). `commitCell` already has a defensive branch for an unreachable collision that returns `ErrNameTaken` (`spawn.go:160`), which is the documented set's own member and so not a precedent for a new error.
3. The path is computed **before `reserve`**, so a panic leaves no reservation, no outstanding count and no half-built cell. A panic in `Spawn` from a `Context` becomes a failure of the calling actor (as any panic in Receive); from a `System` it reaches the caller. For a valid name neither can happen (proof above).
4. It never yields a zero path: the only way out of `childPath` with no panic is a non-zero path.

**Test (P12), written first:** `childPath` on a `spawnTarget` with a parent that has no path, with a name that `Child` rejects (`"a/b"`, `""`, `"a#1"`) and with a System whose address is the zero Address, each asserting a panic whose value is an error that wraps `ErrInvalidPath` (or the no-parent-path error) and that no name was reserved (`outstanding` unchanged). This pins the seam without any new test hook in production code.

**Result:** invariance proven by reading and by P11; defensive failure is an internal-invariant panic before publication, with no change of exported behavior, of the documented error set, or of the contract. **STOP condition (c) did not fire.**

## 8. G-2: what `NewSystem` enforces about names (verification asked by the Owner)
`newSystem` (`system.go`) copies `Config.Name` (or `"default"`) into `name` and builds `address` from it. There is no registry of System names, no package-level state besides the `closedChan` constant channel (`system.go:11`), no uniqueness check and no name validation. So two Systems of one process can have the same name and therefore equal `Address` values; and a name outside Pekko's rule is accepted verbatim. Conclusion: Address equality is **not** proof that two handles belong to the same System instance. The `PathOf` doc comment, the README and the test for P6 state this and assert only what holds: two Systems created with one name report equal Addresses for their own actors.
