### M460b-twice: a documented survivor, with no difference in the effects these tests observe
*(Wording fixed after the Owner's remark: this is NOT a demonstrated general equivalence; the earlier title said "equivalent with respect to the contract".)* A second `handOver` starts a second activation that runs `terminate` again, which is a no-op by design as far as the code reading shows: `beginStartLocked` returns false, `beginTermination` finds no more children, and the `finalizing` guard of `readyLocked` (`hierarchy.go:164-167`) lets only one caller schedule the finalization; that guard is pinned by `TestFinalizationIsScheduledExactlyOnce`. The effects the tests observe (`Done` closing once, one `Terminated`, one `stop-accepted`, the outstanding set, the decider count) do not differ between the mutant and the original, which is why the mutant survives. That is all that is shown. What is **not** shown: with the double hand-over two activations of the same cell can run at the same time, which breaks the invariant stated at `cell.go:93`; an effect of that overlap that no test observes is not excluded, and no proof of general equivalence is offered. It is not detected and not claimed as detected; the runner's classification is unchanged (UNMET). Production was not changed to kill it. The comment above the cell in `judge/mutate_go.py` (lines 169-172) says "no contract effect ... can tell it from the original": read it as the same limited statement (the four effects named there). Rewording it would change `judge/mutate_go.py`, an input of the campaign, and so would require a new campaign for a comment; it is left as is and deferred to the next legitimate change of that file.
