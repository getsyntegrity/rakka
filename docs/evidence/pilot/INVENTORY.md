## Slice 1 — `ActorPath.fromString`

What is ported: `ActorPath.fromString` → `ActorPathExtractor` → `AddressFromURIString` → `PathUtils.split`
→ `RootActorPath./` / `ChildActorPath` (`ActorCell.splitNameAndUid`), plus the outputs `toString`,
`name`, `elements`, `uid`, `toStringWithoutAddress`, `toSerializationFormat` and the parsed `Address`.

Findings worth keeping:
- `fromString` does **not** call `validatePathElement`: `$a`, `a%20b`, `..`, non-ASCII and empty-name-with-uid (`/user/#5`) are all accepted.
- Everything hinges on `java.net.URI(String)` (RFC 2396 + JDK deviations), so the JDK 17.0.21 parser is ported as-is (`pekko-actor/src/identity/jdk_uri.rs`). Unicode classes (`Character.digit/isSpaceChar/isISOControl`) are generated from the JDK (`pekko-actor/tools/GenTables.java`).
- `NumberFormatException` is observable in two places: a bad `#uid` (`For input string: "x"`) and an out-of-int-range octet in an IPv6-embedded IPv4 literal (`Error at index 9 in: "99999999999"`) — the latter escapes `fromString` because Pekko only catches `URISyntaxException`.
- A user info like `%ED%A0%80` decodes to **one** U+FFFD in the JDK (three with Rust's `from_utf8_lossy`); the JDK's malformed-length rules are ported in `decode_utf8_jdk`.
- Strings are `Vec<u16>` (Java `String` semantics: lone surrogates, UTF-16 positions).

Out-of-scope dependencies hit by this slice: **none** for `fromString` itself. Pending parts of the same classes that touch
out-of-scope modules (recorded here so they are not forgotten):
- `ActorPath.toStringWithAddress` / `toSerializationFormatWithAddress` take the *system's* default address, which comes from the remoting provider (`RemoteActorRefProvider`); for the local provider it is a plain `Address`. Port with an injected address, leave the remoting-driven choice of address out. Also uses `IgnoreActorRef.isIgnoreRefPath` (classic internal, in scope for slice 2).
- `Address` serialization (`protobuf`/`ActorRefResolveCache`) belongs to remoting/serialization: out of scope.

## Slice 2a — local `ActorSystem` (notes)

Runtime: `ActorCell` + system messages + `ChildrenContainer` + mailbox + dispatcher thread pool, with the real guardian chain
(`/user` and `/system` watched through `Watch`/`DeathWatchNotification`, root guardian supervised by the bubble walker).
Settings are plain defaults (no HOCON `Config`); no event stream, scheduler, extensions or CoordinatedShutdown yet.

Not representable / not covered yet:
- `actorOf(props, null)` ("actor name must not be null"): a Rust `&str` cannot be null.
- A panic in an actor is handled as "stop" instead of supervision (slice 3).
- `/system/deadLetterListener`, termination hooks, `ActorSystem.uptime/startTime/settings`.
- Reusing a name right after `stop` is a race in Pekko itself (`isTerminated` is true slightly before the parent
  releases the name), so scenarios never rely on it. Likewise nothing is asserted between `terminate` and `await-system-terminated`.

## Slice 2b — tell, sender, mailbox, dead letters (notes)

What is verified against Pekko 2.0.0 (recorded first, then replayed against the Rust CLI):
- `tell` with and without sender: without one the receiver (and the `DeadLetter`/`UnhandledMessage` events) see `pekko://sys/deadLetters`.
  `forward` keeps the sender; `echo` replies to it.
- Ordering: messages from one sender to one receiver are processed in order (exact lists for small cases, `inOrder` invariant
  for 1000 messages and for 2/3/4/8 concurrent senders — interleavings between senders are never compared).
- `PoisonPill`: earlier messages are processed, later ones become dead letters; sent to a dead actor or to `deadLetters` it is
  `DeadLetterSuppression` and publishes nothing (as does `Terminated`).
- Dead letters after confirmed termination: `DeadLetter(message, sender, recipient)`; tell vs stop races are checked as invariants
  (received is a prefix of what was sent, the rest are dead letters exactly once).
- Unhandled messages publish `UnhandledMessage(message, sender, recipient)`; handled ones do not.
- Throughput: with a single-thread dispatcher (`thread-pool-executor`, fixed size 1) and a gate actor blocking that thread while the
  mailboxes are filled, Pekko runs exactly `throughput` messages per turn and re-queues the mailbox at the end:
  `throughput = 1, 2, 3, 5, 7, 10, 100` and uneven mailboxes are recorded and replayed. A pre-start barrier is required: without it the
  order in which mailboxes enter the executor queue is a race even in Pekko (the recorder flagged those cases as noisy).
- Guardians run on a separate `internal-dispatcher` (4 threads), as in Pekko.

Design decisions: messages are `Arc<dyn Any + Send + Sync>` (immutable, shareable, so dead letters and the event stream can fan them
out); `Actor::receive` returns `bool` (`false` = Pekko's `unhandled`).

Pending contracts (not covered yet, so do not rely on them):
- `tell(null)` ("Message is null", `InvalidMessageException`): a Rust value cannot be null.
- Mailbox types: bounded (`mailbox-capacity`, push timeout), priority, control-aware, stashing; `Props.withMailbox`/`withDispatcher`.
- `become`/`unbecome`, `Identify`/`ActorIdentity`, `Kill`, `receiveTimeout`, `ActorSelection`.
- `throughput-deadline-time`, fork-join vs thread-pool executors (only the single-thread FIFO case is observable and compared).
- `DeadLetter` logging/`log-dead-letters`, `SuppressedDeadLetter`/`Dropped` event classes, event stream subclassification.
- Dead letters of dead letters are dropped (needed to avoid a loop when a subscriber dies); Pekko's exact rule is not verified.
- `Terminated` unhandled should raise `DeathPactException`; failures in `receive` stop the actor (supervision is slice 3).
- Concurrency stress beyond 8 senders / 1000 messages, and fairness across actors on a multi-thread dispatcher.

## Slice 3a: hierarchy and DeathWatch (notes)

What is verified against Pekko 2.0.0 (recorded first with `rust-anything app record`, then replayed):
- Children: `context.actorOf` (named and anonymous: `$a`, `$b`, ... per parent), `context.child(name)`, `context.children`, grandchildren,
  the same child name under different parents, `InvalidActorNameException` for a sibling collision and for the 16 invalid names tried
  under a parent (same rules as the top level), `IllegalStateException("cannot create children while terminating or terminated")` from
  `postStop` (with and without children).
- Parent termination with live children: only the guaranteed orders are compared (`await-life`): a child's `postStop` precedes its parent's,
  a `postStop` precedes the `Terminated` the watchers get. Stopping by system, `PoisonPill` and `context.stop(self)`; stopping a middle node
  stops its subtree and spares its siblings; `context.stop` of a non-child works (`h22`).
- A terminating parent that watches its children gets no `Terminated` (the user mailbox is suspended; those messages end up as suppressed dead letters).
- **Name reuse needs a confirmation by the parent.** `isTerminated` is true before the parent has released the name, and a third-party
  watcher's `Terminated` is *not* a confirmation either (the parent processes its own `DeathWatchNotification` independently).
  Two valid barriers: (1) the parent watches the child and has received `Terminated` (the name is released in the same system-message step
  that queues it), (2) the harness polls `context.child(name)` until it is empty (`await-child-gone`). Top-level names cannot be confirmed
  (the guardian is not scripted), so scenarios never reuse them.
- **Identity.** Old and new reference with the same path: `ActorPath` equal, `toString` equal, `uid` different, `ActorRef` **not** equal
  (`equals` is `path.uid == other.path.uid && path == other.path`). A message to the old reference is a dead letter (recipient path
  equal to the new actor's) and the new actor does not see it; `context.stop`/`PoisonPill` through the old reference leave the new actor alone;
  `context.child(name)` returns the new one.
- DeathWatch: `Terminated(actor, existenceConfirmed, addressTerminated)` with `sender == actor`; watching a live actor (`true`), an already terminated
  one (an immediate `Terminated` with `existenceConfirmed = false`, no dead letter is published); repeated watch of a *live* actor gives one `Terminated`, while each `watch` of an *already dead* actor gets its own (the first one clears the watch, `w05`, awaited in between: a `Terminated` that is still queued is not queued twice, `terminatedQueued`);
  `watch`/`unwatch` of self are no-ops; unwatch before the stop, never watched, twice, and watch-unwatch-watch; a watcher that dies first;
  `Terminated` events name the exact instance (`is`) when a new actor reuses the path, including a new instance watching/unwatching its dead predecessor.
- **`terminatedQueued` (found by the oracle, not in the first Rust port).** `unwatch` also cancels a `Terminated` that is already in the watcher's
  mailbox. Verified with a blocked watcher (`w21`, `w23`; `w23` makes the notification reach the watcher's system queue deterministically by using the
  *parent* as the watcher, because a parent is notified before any other watcher). `w22`/`w24` are the controls: without `unwatch` it is delivered.
- **Equality by uid, not by path.** The first port compared the actors in `Watch`/`Unwatch` by path; Pekko compares `ActorRef`s (path + uid).

Verification: 415/415 recorded cases replay (6 consecutive replays), `tools/fuzz_hier.py` 3 x 1000 scenarios (~29,500 steps each, 0 divergences, 0 oracle timeouts),
regression fuzzers unchanged (0 divergences), 14/14 mutants detected.

Harness additions (same JSON DSL in `Scenario.java` and `scenario.rs`): `do` (run a command inside an actor: `spawn-child`, `child`, `children`, `watch`,
`unwatch`, `stop`; `async` queues it without waiting), `await-child-gone`, `compare-refs`, `await-life` (sorted lifecycle events + only the guaranteed
`before` constraints), `events-now`, `events-sorted`, behaviour option `post-stop-spawn`, and `terminated` events with `is` = label of the equal reference.

Races deliberately **not** compared (Pekko does not guarantee them): the order in which one watcher receives `Terminated` for a parent and for its child
(the child tells its parent first, then its watchers, so the parent can finish and notify first; the fuzzer found this, `events-sorted` is the fix),
which of several watchers is notified first, and name reuse right after `stop` without a parent confirmation.

Mutants of 3a (all run on scratch copies; the real tree hash was identical before and after): `ref-identity-is-path`, `children-match-by-path`,
`watch-self-check-by-path`, `unwatch-keeps-queued-terminated`, `unwatch-is-noop`, `watch-dead-confirms-existence`. One candidate,
`terminated-delivered-while-stopping` (a terminating parent still queues `Terminated`), is an *equivalent* mutant: the user mailbox is suspended and then
drained into dead letters, where `Terminated` is suppressed, so nothing observable changes; it was dropped from `check_divergence.py`.

Pending for 3b and later (left out on purpose): `DeathPactException` (an unhandled `Terminated`), `Kill`, supervision strategies and restart semantics
(`Failed`, `Supervise` bookkeeping, `preRestart`/`postRestart`), `watchWith`, `ActorSelection`/`Identify`, `context.parent`/`context.system` accessors,
`deathwatch` of `FunctionRef`/remote refs and `AddressTerminated` (remoting), `ask`, timers. Not covered: `watch` of `deadLetters`, hierarchies deeper
than 4, more than 3 watchers per target in the fuzzer, concurrent stops of several subtrees (only invariants would be comparable).

## Slice 3b-1: failure handling with the default strategy (notes)

Recorded from Pekko 2.0.0 first (`tools/make_scenarios_3b1.py`, 27 scenarios, `cases/scenario-3b1.jsonl`), then implemented test-first
(`pekko-actor/tests/classic_failures.rs`). Red evidence: 7/7 Rust tests failed and the replay was 475/500 before the runtime change; after it, 7/7 and 500/500.

- An exception in `receive` (a `Throwable` thrown with `fault::throw`, or any panic = `java.lang.RuntimeException`): the actor reports `Failed` to its parent,
  its mailbox is suspended, the failing message is lost (not a dead letter), the rest of the mailbox is kept in order.
  Default decider: `ActorInitializationException`/`ActorKilledException`/`DeathPactException` stop the child; everything else restarts it.
- Restart (`Recreate`): `preRestart(reason, message)` on the old instance (default: stop all children, then `postStop`), wait for the children to die
  (`Recreation` container state), new instance from `Props`, `postRestart(reason)` (default: `preStart`), mailbox resumed. Watchers get no `Terminated`;
  the `ActorRef` stays valid; children are **not** recreated; per-instance state starts again.
- `Kill` (`ActorKilledException("Kill")`) stops the actor: `postStop` only, no restart hooks, watchers get `Terminated`; a queued message or a later `Kill` is a dead letter.
- An unhandled `Terminated` is `DeathPactException`: the watcher stops (not restarted).
- A failure in `preStart` stops the actor and **`postStop` is not called** (found by the oracle: only `pre-start` is recorded).
- Failures inside `preRestart` are ignored (Pekko only logs them); a failing `postRestart` is a `PostRestartException` (stop) — implemented, not yet recorded.

Harness additions (Scenario.java and scenario.rs): behaviour options `throw-on`, `throw-in-prestart`, `ignore-terminated`, `numbered`; events `pre-restart`/`post-restart`;
message `{"special":"Kill"}`. Mutants added: `kill-restarts-instead-of-stopping`, `deathpact-restarts-instead-of-stopping`, `init-failure-restarts-instead-of-stopping`,
`exception-stops-instead-of-restarting`, `post-restart-not-called`, `pre-restart-without-message`, `failure-does-not-suspend-mailbox`.

Not yet done in 3b: `SupervisorStrategy` (OneForOne/AllForOne, custom deciders, `maxNrOfRetries`/`withinTimeRange`), `Resume`, `Escalate`, children being suspended while
their parent fails, ask, timers, `Failed` from a failing `postRestart` verified against Pekko. Gotcha: `cargo llvm-cov clean --workspace` after source edits, or the report shows shifted lines.

## Slice 3b-2: OneForOneStrategy, decider, Resume / Restart / Stop, restart limit (notes)

Recorded from Pekko 2.0.0 first (`tools/make_scenarios_3b2.py`: 19 directive scenarios + 10 limit scenarios, `cases/scenario-3b2.jsonl`), then implemented test-first
(`pekko-actor/tests/classic_supervision.rs`, unit tests in `actor/supervision.rs`). API: `supervision::{Directive, OneForOneStrategy, default_decider}` and
`Actor::supervisor_strategy()`; the decider is a total function `&Throwable -> Directive` (Pekko's partial function + default for the rest is expressed by calling `default_decider`).

- **Resume**: same instance, state kept (per-instance counter keeps counting), no restart hooks, the failed message is lost (not a dead letter), the next queued message is processed, the reference stays valid.
- **Restart**: as 3b-1 (preRestart -> postStop, new instance, postRestart -> preStart; counter reset; the next queued message goes to the new instance).
- **Stop**: the child stops, only `postStop` runs; messages queued behind the failing one and later ones are dead letters; the supervisor gets `Terminated` if it watches.
- **Healthy sibling**: a directive applies to the failed child only; its sibling sees nothing, with all three directives and with two children failing at once.
- **`maxNrOfRetries`** (counted per child, only for Restart): `0` stops at the first failure with no restart hooks; `n` allows exactly `n` restarts, the `n+1`-th failure stops the child;
  Resume and Stop never count; a negative value (`-1`, `-5`) is unlimited; a new child with the same name starts with a fresh counter.
- Not done (separate slices): the `withinTimeRange` window and its reset (needs controlled time), `AllForOne`, `Escalate`, ask, timers.
- Race found while recording: after a Stop, the supervisor's `Terminated` arrives after the child's `postStop`, so a scenario must await it (`EV("p", 2)`) before reading the supervisor's events.

Harness (Scenario.java / scenario.rs): behaviour option `supervisor: {"max": n, "decider": {<exception message>: "resume"|"restart"|"stop"}}` (unmapped exceptions use the default decider),
`throw-on` accepts a list. Mutants added: `resume-confused-with-restart`, `restart-confused-with-resume`, `restart-limit-allows-one-more`, `restart-limit-allows-one-fewer`,
`minus-one-is-not-unlimited`, `restart-counter-shared-by-siblings`.

## Slice 3b-3: Escalate (notes)

Recorded from Pekko 2.0.0 first (`tools/make_scenarios_3b3.py`, 17 scenarios, `cases/scenario-3b3.jsonl`; every scenario was run 12 times against the oracle with identical output, names are unique
in their first 24 characters), then implemented test-first (`pekko-actor/tests/classic_escalate.rs`, 11 tests). Red evidence: the replay was 529/546 (all 17 new cases diverged) and the first test did not
compile (`no variant Escalate`); green: 11/11 tests and 546/546. Three levels: `g` (top-level supervisor) -> `p` (supervisor that escalates) -> `c` (throws in `receive`).

What Pekko does (all recorded):
- The decider of `g` is called with the **same exception the child threw** (class and message untouched; `ActorKilledException: Kill` stays an `ActorKilledException`). `p`'s own decider also runs first.
  With no mapping at `g` its default decider applies to that cause (`IllegalStateException` -> Restart, `ActorKilledException` -> Stop).
- The directive applies to **`p`** (the failed actor from `g`'s point of view), not to `c`. `p` suspends its mailbox and its other children while `g` decides; the failed `c` is not suspended a second time.
- **Resume** of `p`: no hooks, same instance and references; `c` gets its resume with the cause and carries on (failed message lost, queued messages processed); a healthy sibling is resumed too and loses nothing.
- **Restart** of `p`: `preRestart(reason = the child's exception, message = a sysmsg.Failed)`, `postStop`, new instance, `postRestart`, `preStart`; `c` and its siblings are stopped by the default `preRestart` and not recreated;
  messages queued in `c` are dead letters; the reference to `p` stays valid and `g` gets no `Terminated`; the new `p` instance escalates again.
- **Stop** of `p`: `p` and its children stop (`postStop` only), `g` gets `Terminated(p)`, later messages are dead letters.
- `g`'s `maxNrOfRetries` counts the restarts of `p` (0: first escalation stops `p`; 1: the second stops it). `p`'s own limit is irrelevant to an escalation.
- A failure `p` resolves itself (e.g. Resume) never reaches `g`.

Implementation: `Directive::Escalate`; `Cell::escalate` (in `actor/cell.rs`, next to the other directive handling) = `handleInvokeFailure` for the supervisor: suspend itself and its other children, remember the
escalated child, report `Failed(p, cause)` to its parent; `fault_resume` resumes the escalated child (with the cause) and the other children (without it); new system message `Suspend`, `Resume.cause` is optional,
public message class `Failed` (what `preRestart` receives). Harness: `supervisor.decider` accepts `escalate`; `supervisor.log-decisions: true` records `{"ev":"decide","cause","directive"}` (off by default, so the 529
older recordings are unchanged).

Mutants added: `escalate-resolved-locally` (the parent resumes locally what it should escalate), `escalate-alters-cause` (the escalation rewraps the cause: observable in `g`'s `decide` event, so no fallback was needed),
`escalate-never-resumes-children`.

Not covered (own slices or out of scope): escalation to a guardian (the user guardian's own failure handling), `AllForOne`, `withinTimeRange`, ask, timers. Not ported: suspending the children of an actor that fails by
its own exception (only the escalation path suspends/resumes children; recorded scenarios cannot tell the difference yet).

Final verification of 3b-3 (final tree): replay **546/546** (529 older + 17 new); `cargo test --workspace` green; `cargo clippy --workspace --all-targets -- -D warnings` clean; coverage gate
`tools/coverage.sh` 96.25 % (cell.rs 95.28 %, supervision.rs 100 %). Mutant regression **30/30 DETECTED, control 546/546** (`rust/divergence-reports/SUMMARY.md`, logs `run-3b3-*.log`). The full run first ended with exit 2:
two older mutants (`resume-confused-with-restart`, `restart-confused-with-resume`) had stale patches after `Resume.cause` became an `Option` (PATCH_ERROR / BUILD_ERROR, not verdicts); their patches were updated and they were re-run
separately (both DETECTED, control clean). Pass counts of the three new mutants: 530, 530, 540 of 546.

## Slice 3b-4: the subtree of an actor that failed on its own is suspended (notes)

Recorded from Pekko 2.0.0 first (`tools/make_scenarios_3b4.py`, 6 scenarios, `cases/scenario-3b4.jsonl`; each ran 10 times against the oracle with identical output). `g` supervises `p`, `p` fails in
`receive` and owns an active child `c` (also: two children, a grandchild). `g`'s decider logs and then waits on a **hold** (`supervisor.hold`, released by the `open-hold` op): a barrier, not a sleep, so the
decision is pending for as long as the scenario needs. During the pause the harness sends messages to the children and `await-quiet` (the only bounded wait, 300 ms, used to prove an absence) checks they were not processed;
recovery is awaited by events only.

What Pekko does: **every child of the failed actor is suspended (recursively: grandchildren too) until its supervisor decides**; nothing is processed meanwhile. Resume: p and all children continue, the messages that
arrived during the pause are processed in order. Restart: the children are stopped by `preRestart`, the messages sent during the pause are dead letters (never processed). Stop: the whole subtree stops.

(`ActorCell::fail`, shared by `handle_invoke_failure` and `Escalate`): suspend the mailbox and every child except the escalated one; `Suspend` is recursive (`fault_suspend`); `fault_resume` resumes the current
children (the escalated child with the cause, the others without it). Green: 5 tests in `tests/classic_suspension.rs`, replay 552/552. Harness: `supervisor.hold`, ops `open-hold`, `await-quiet`.

## Slice 3b-5: AllForOneStrategy (notes)

Recorded from Pekko 2.0.0 first (`tools/make_scenarios_3b5.py`, 14 scenarios, `cases/scenario-3b5.jsonl`: 9 directive scenarios `o*`, 5 restart-limit scenarios `r*`; each ran 20-40 times with identical output;
the order of two `Terminated` is a race, so those steps use `await-events {"sorted": true}` / `events-sorted`). A supervisor `p` with children `c1` (fails) and `c2` (healthy), `strategy: "all-for-one"`.

- **Resume**: only the failed child; the healthy one sees nothing (no hooks, state kept).
- **Restart**: **both** children restart (`preRestart`, `postStop`, new instance, `postRestart`, `preStart`); state restarts from zero in both; references and uids stay valid, no `Terminated`. The healthy child's
  `preRestart` gets the **failed child's exception and no message** (`None`); the failed child gets the exception and the message that failed. Messages queued behind the failing one go to the failed child's new instance.
- **Stop**: **both** children are stopped (the healthy one too, `postStop` only); messages sent later are dead letters; `p` gets two `Terminated` (racy order).
- **Held decision**: while the decision is pending the healthy sibling is not suspended and keeps processing; it is suspended and restarted only when the decision is applied.
- **Restart limit**: it is checked with `forall` over all children: with `max = 0` the first failure stops both; with `max = 1` the first restart restarts both, then a failure of the *other* child exhausts the limit and stops
  both; Resume never counts; a negative limit is unlimited. A restart of all children counts once for each child.

Red: replay 554/566 (12 of the 14 diverged; `o01` and `o09` already agreed: characterization, Resume is the same as in OneForOne) and 4 of 6 Rust tests failed. The change was made in two steps, each shown red then green:
first Restart on all children (`restart_replaces_every_child` green, Stop and limit tests still red: 3/6), then Stop and the exhausted limit on all children (6/6). Final replay 566/566.

API: `supervision::{AllForOneStrategy, SupervisorStrategy}`; `Actor::supervisor_strategy()` now returns `SupervisorStrategy` (`OneForOneStrategy`/`AllForOneStrategy` convert with `.into()`).
Implementation: `ActorCell::process_failure` (Pekko's `processFailure`), in `actor/cell.rs` next to the other directive handling; the healthy children are suspended before their `Recreate`. Mutants: `all-for-one-degrades-to-one-for-one`
(AllForOne behaves as OneForOne), `all-for-one-stop-only-failed`; the older mutants whose patterns moved with the refactors were re-targeted.
